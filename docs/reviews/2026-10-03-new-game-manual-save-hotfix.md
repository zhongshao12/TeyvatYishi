# 新档崩溃与手动存档覆盖修复

## 用户确认的行为

- 普通“保存”更新当前手动存档的文件 ID 和节点 ID；仅“另存为新节点”新增。
- 自动存档仍保留独立历史节点；同名旅行者的不同旅程不能混用目标。
- 不自动删除现有重复文件，不合并或推送 Git 分支。

## 根因与修复

1. 新档聊天回合快照的剧情编织数据是稀疏 v4 持久化格式，却被 `fromLegacyTurnCheckpoint` 直接当成完整对象投影。`segment.章节标题` 等资源字段未存入快照，导致展开数组时崩溃。现在在快照还原边界先补回内置资源及玩家逐字段修改，再转换为正式 DTO；不是将缺失字段简单清空。
2. 手动保存原先总是创建新树节点，而数据库总是 `add` / 预留新桌面 ID。现在显式记录当前手动目标，普通保存保持原节点及其父节点，另存为建立新节点。重启后读取自动档时沿同树祖先定位手动目标，不按姓名匹配。并发手动请求串行处理，切档后尚未执行的请求取消。
3. 覆盖手动档前，将引用其旧内容的增量自动档转为完整检查点，保持历史快照不变。代价是这些已有自动档可能稍增体积，但不新建对应文件或节点。
4. 桌面依赖档写入失败时不覆盖手动基线；当前手动主文件无法替换时也报失败，不能仅更新 IndexedDB 后假称成功而再次读到旧主文件。
5. 存档窗口的大屏和小屏分别提供保存与另存为入口；设置页、快捷键和导出时的普通保存沿用覆盖行为。
