# 提瓦特 120 名角色聊天头像实施计划

**Spec:** `docs/superpowers/specs/2026-09-01-teyvat-120-chat-avatars-design.md`

## Global Constraints

- 最终必须恰好有 120 张 256 × 256 WebP：69 张五星、51 张四星。
- 安柏沿用现有已确认资产，不覆盖。
- 每个角色必须独立生成，并保持安柏样张的尺寸、构图、辨识度与压缩标准。
- 项目资源必须位于 `public/assets/teyvat-avatars/characters/<rarity>-star/`。
- 原创生成，不复制官方或第三方图片；禁止文字、Logo 和水印。
- 聊天接入必须有可重复的自动验证，不能依靠手工路径表散落在组件中。

## Task 1：名单与生产基础设施

- 建立 120 人机器可读清单，包含英文名、slug、星级、元素、输出路径和生成状态。
- 保留安柏现有 manifest 信息。
- 增加头像审计脚本：检查数量、缺图、重复路径、尺寸、格式和体积。
- 增加 WebP 优化脚本，统一 256 × 256、quality 78、effort 6。

## Task 2：批量原创绘制

- 按元素和星级拆分为互不重叠的制作批次。
- 每张使用独立内置 imagegen 调用，依据角色标志性外观编写提示词。
- 逐张查看生成结果；不合格时只针对一个问题迭代。
- 把最终原图压缩后放入对应星级资产目录。

## Task 3：资产清单与聊天接入

- 从完成的清单生成或维护统一头像目录。
- 在 `data/builtinAvatars.ts` 的现有入口注册提瓦特头像及别名匹配。
- 保持现有 NPC 自定义头像优先级不变，仅为无自定义头像的角色提供默认值。
- 添加解析测试，覆盖英文名、中文名、别名、未知角色和自定义旅行者边界。

## Task 4：整体验收

- 生成 120 人联系表，检查构图、风格和色彩偏差。
- 执行头像审计脚本，确认 120/120、69/51、全部 256 × 256 WebP。
- 执行相关单元测试和生产构建。
- 抽样在聊天 UI 的圆形头像槽中检查 64 px 与 32 px 可读性。

## 生产台账约定

- `.superpowers/sdd/2026-09-01-teyvat-120-chat-avatars/progress.md` 记录批次、提示词、源文件、输出文件、审计结果和必要裁决。
- 没有 Git 元数据，因此本计划不使用提交范围或 worktree；所有评审基于明确文件清单、检查结果和可视联系表。
