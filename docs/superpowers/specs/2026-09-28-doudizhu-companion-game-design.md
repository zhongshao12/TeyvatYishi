# 斗地主同伴游戏设计

## 目标与已确认范围

把侧栏现有“纪年”页面换成可与两位已结识角色游玩的完整三人斗地主。每局结束，两位受邀角色各固定增加 5 点好感，且每人各得到一条与该局真实过程有关的同行记忆；不同好感阶段影响角色的出牌倾向和对局台词。牌局可随正常游戏存档保存，重新载入后接着玩。无下注、无摩拉/积分收支。底层旅行时间、旅程天数与现有纪年数据保留，其他系统仍可使用原时间线构建逻辑。

## 页面与角色邀请

沿用现有侧栏路由键 `timeline` 以兼容已保存的页面选择，但将导航名称和内容改为“斗地主”。新面板独立于主聊天回合，不调用正文模型，也不自动推进游戏时钟。可从当前存档已结识、未归档、具稳定 NPC ID 的同伴中邀请两名不同角色；已经在别处的角色可以接受邀请，但牌桌叙事只能说“通过约定/见面加入牌局”，不能把他们自动改成主线队伍成员。邀请失败、NPC 消失或存档切换时，给出明确提示并允许返回选人。

## 牌局规则

使用 54 张牌、三人各 17 张与 3 张底牌。依次叫 1/2/3 分或不叫，最高叫分者为地主并取得底牌；无人叫分时重新发牌。地主先出牌，之后按顺序轮流压制或不要；两家连续不要后由上一位出牌者重新领出。支持单张、对子、三张、三带一、三带二、顺子、连对、飞机及其常见带牌、四带二、炸弹和王炸；相同牌型与张数按主牌点数比较，炸弹可压普通牌，王炸最大。第一位出完手牌者决定胜负：地主单独获胜，或两位农民共同获胜。春天/反春只作牌局记录，不产生下注或额外好感。无合法出牌时只能“不要”；领出时不能“不要”。

点数顺序固定为 3–A、2、小王、大王；顺子、连对、飞机的连续主体不得含 2 或王。顺子至少五张，连对至少三对，飞机至少两组三张；飞机可不带牌，或每组三张各带一张单牌/一对，不能把主体牌重复算作翅膀。四带二支持两张单牌或两对，但不作为炸弹压其他牌型。牌型相同且长度相同才可比较；叫分只决定地主，不兑换游戏货币。

洗牌由存入牌局的种子决定。每一步动作先由纯规则引擎验证，再原子地写入牌局状态；重复点击、重放存档或快速自动回合不得重复结算。

## NPC 出牌与人物表现

NPC 不依赖 API 才能完成对局。规则层先枚举合法动作，策略层根据牌面与阵营选择，确保每次都合法。人物性格可从已存性格/说话方式与原著角色档案提取简短风格标签；好感度只影响在合法动作之间的偏好：低好感更重视自保与稳妥，中等好感更愿意配合农民队友，高好感更会记住玩家的习惯、适度给队友留牌，但绝不故意输、窥牌或共享不该知道的手牌。地主与农民的合作逻辑始终优先于关系表演。台词用角色风格模板与对局事件组合，避免每步都调用模型；必要时可在局后异步润色记忆文本，但规则、好感与存档提交不依赖它。

## 存档、好感与记忆

在 `TeyvatGameState` 增加可归一化的斗地主状态切片：当前牌局 ID、邀请者稳定 NPC ID、洗牌种子、牌堆/手牌、叫分、角色、轮次、桌面牌、过牌数、操作日志、结算标记，以及受限长度的最近对局摘要。旧档缺失该切片时自动生成空状态，不触碰世界时间字段。载入中途牌局时先验证人数、牌数、轮次和日志一致性；损坏的牌局不结算好感，提示玩家返回新局。

胜负确认后，用牌局 ID 做幂等键，在同一次状态更新中给两名 NPC 各加 5 点好感（遵守现有好感上限、关系称谓与历史记录规则），各写入一条含角色、阵营、胜负和 1–2 个真实牌局片段的共享记忆。中途退出、重开、重复载入、无人叫分重新发牌均不发奖励。牌局操作日志做长度上限，仅保留恢复所需状态与最近摘要，防止长存档膨胀。

## 边界与验证

规则引擎、NPC 策略、结算与 UI 分层；纯规则引擎无 React/存档依赖。测试覆盖所有牌型比较、叫分/过牌/终局、NPC 永远只出合法牌、三个好感阶段的策略差异、玩家与 NPC 的地主/农民组合、+5 和记忆幂等、旧档空状态、中途保存/恢复及损坏局面拒绝结算。UI 测试覆盖邀请、出牌提示、可访问的键盘操作、手机/同伴数据同步，以及“纪年”页面被替换但时间字段不变。最终运行 Vitest、TypeScript、ESLint 和生产构建。
