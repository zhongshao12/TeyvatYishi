# 旅行者纪事 TeyvatYishi

旅行者纪事是一个以 **React 19 + TypeScript + Vite + Tailwind CSS** 构建的同人叙事 Web 应用。它尝试把 AI 互动小说、跑团式剧情推进、世界书、结构化变量、伙伴档案、信使通讯、蒸汽鸟报演化、记忆压缩、原著图鉴和文生图资产管理整合成一个完整的前端游戏体验。

当前 v1.6.0 在正式提瓦特运行时基础上，合并元素与天赋页面，加入右侧手账手机页和朋友圈独立草稿，并加固手机身份、异步生图、设置保存与存档隔离。仍使用同一份 schema 2 状态根，不重置已有玩家存档。

最新版本从 [GitHub Releases](https://github.com/zhongshao12/TeyvatYishi/releases) 下载。源码包用于开发；Web 成品包需要 HTTP 服务，不能直接双击 `index.html` 使用。当前发布不包含已验证的新 Windows 安装器，已发布的 v1.6.0 也没有包含变量与记忆协同架构 2.0。

源码开发版说明（2026-10-18）：变量、记忆与存储 2.0 已有可测试的新核心实现，但仍是默认关闭的开发入口，不代表上面的 v1.6.0 发布包已更新。新核心只使用独立的新档，不读取或迁移旧版存档，也不会删除旧数据。经用户调整，这次先完成现有问题修复和工程复验，1000～5000 回合长期可靠性验收暂缓；没有据此宣称长期性能已达标。当前源码改动与实际交付边界见[更新记录](CHANGELOG.md)。

## 项目目标

旅行者纪事的核心目标是做一个“可持续游玩”的 AI 叙事框架。

很多 AI 剧情应用能生成漂亮的段落，但难点在于长期游玩后容易失忆、人物重复、变量散乱、剧情推进不可控。这个项目试图用前端数据模型和多层提示词协议解决这些问题：

- 用世界书和提示词模块约束叙事风格、开局规则与变量边界。
- 用变量模型把正文中的事实结算为结构化存档。
- 用伙伴、背包、信使、蒸汽鸟报、记忆、图鉴等系统承接正文里发生过的事。
- 用可视化面板让玩家能检查、修正和继续扩展世界状态。
- 用文生图工作台逐步把角色头像、立绘、场景壁纸和相册资源接入叙事体验。

## 当前功能

### 新游戏与主线开局

- 五步“踏上旅途”向导：世界、角色、元素、开局锚点、总览。
- 六个官方开局预设覆盖蒙德、璃月、稻妻、须弥、枫丹与纳塔，并创建互不共享引用的独立游戏状态。
- 支持自定义旅行者姓名、性别、来历、外貌、性格、背景、能力；玩家旅行者与空 / 荧同时存在于世界设定中。
- 支持剧情模式、难度、起始场景、阵营与元素选择。
- 原著轨道可记录遵循、偏离、阻塞和回归，已阻塞锚点不会因关键词命中而被静默推进。

### AI 主剧情

- 支持流式 / 非流式回复。
- 主剧情输出先解析为 `NarrativeTurn`，再把有证据的事实转换为受控领域命令；只有整棵状态校验成功才会一次提交。
- 支持重新开局、重 roll、行动选项快捷输入。
- 回合正文会进入领域结算、记忆整理、蒸汽鸟报推演等后续流程。

### 世界书与提示词模块

- 内置开局规范、伙伴档案、变量系统、蒸汽鸟报、信使等提示词模块。
- 世界书管理支持内置与额外世界书分栏。
- 内置世界书可编辑、启用和禁用，便于玩家调试自己的叙事规则。
- 开局世界书预设会在首次启动时注入 IndexedDB。

### 变量系统

- 独立变量模型读取主剧情正文，并输出结构化变量命令。
- 支持更新旅行者、世界、NPC、信使、背包、元素进度等状态。
- 对背包物品、NPC 档案、NSFW 档案、元素状态机等字段有校验和兜底。
- 会过滤错误字段、占位符对象、旧字段名和不该写入的系统。
- NPC 归一化层会合并同一人的别名、状态称呼和临时称呼，减少重复建档。

### 伙伴系统

- 伙伴 / 路人分栏管理。
- 记录姓名、别名、性别、关系、好感度、阵营、是否同行、初见与最近回合。
- 支持人物介绍、外貌、穿着、说话方式、性格、装备摘要和同行记忆。
- 原著角色会作为重要伙伴处理。
- 支持头像槽位、角色立绘、图像档案和 NSFW 档案预留。

### 背包与装备

- 方格背包 UI，支持分类筛选和物品详情浮层。
- 物品支持料理、消耗品、圣遗物、武器、风之翼、小道具、纪念品、关键道具等分类。
- 装备系统包含武器、圣遗物五件、风之翼与小道具槽位。
- 装备只作为叙事状态与角色形象的一部分，不扩展复杂词条、强化材料、套装数值或抽取养成。
- AI 写入物品时有解析兜底，避免不完整或错误格式导致界面崩溃。

### 记忆系统

- 当前设计只保留即时、短期、长期三层记忆。
- 即时记忆用于记录每回合刚发生的原始事件。
- 短期记忆由即时记忆压缩而来。
- 长期记忆只保留稳定事实、主线转折、关系变化、不可逆后果和长期目标。
- NPC 同行记忆直接挂在伙伴档案中，服务角色关系连续性。

### 信使系统

- 冒险家协会信使作为独立通讯终端，不直接复用主聊天。
- 支持联系人、会话、主动来信种子、未读状态等数据结构。
- 信使内容可以读取主剧情记忆、NPC 档案、蒸汽鸟报和上下文。
- 后续目标是让短信、群聊和远程回应成为主线之外的叙事延伸。

### 蒸汽鸟报、剧情编织与图鉴

- 蒸汽鸟报用于后台公开事件推演。
- 剧情编织系统用于管理原著剧情轨道、自制剧情轨道和当前推进段。
- 图鉴系统用于保存和检索原著资料、角色、地点、阵营、术语、事件等。
- 内置公开预设资源位于 `public/codex-presets/` 和 `public/worldbook-presets/`。

### 相册与文生图工作台

- 相册以角色为中心管理视觉资源。
- 支持手动生成、资源库、角色锚点、场景壁纸、规则中心、生成队列、历史与整理等工作台入口。
- NPC 图像档案支持头像槽位、立绘、角色锚点和 NSFW 部位图槽位。
- 规则中心支持规则模板、模型规则集和风格预设。

## 本地运行

环境要求：Node.js >= 22（部分回归脚本直接 import .ts 并依赖 Web Crypto / IndexedDB，旧版本 Node 无法运行完整测试套件）。

安装依赖：

```bash
pnpm install
```

启动开发服务：

```bash
pnpm dev
```

构建生产版本：

```bash
pnpm build
```

项目不会自带任何 API Key。运行后需要在应用设置中配置自己的模型接口。

### 本地 Gemma4 · 128k（可选）

已用 Ollama 导入并建立 `gemma4-heretic-128k:latest` 时，可在“设置 → API 接口 → 总接口设置”点击“添加本地 Gemma4 · 128k”。初始地址为 `http://127.0.0.1:11434/v1`，温度 `0.9`、`top_p=0.95`，上下文标记为 `131072`，单次输出上限为 `8192`。`ollama` 只是本地接口的占位 Key，不是云端密钥。

新增配置不会切换当前主模型，也不改动各功能的独立接口。先测试，再按需要点击“启用此配置”和保存。思考模式可选“跟随模型默认 / 开启思考 / 关闭思考”；控制的是本地模型的实际开关，正文只展示最终回复。思考也会占用输出额度，可能延长等待。

实际上下文必须在 Ollama 的 Modelfile 中设置 `PARAMETER num_ctx 131072`；网页里的数值不能替代服务端配置。项目不安装、导入或修改模型文件。请保持本地模型服务运行。

通过本机 `pnpm dev` 或 `pnpm preview` 运行时，此方案会使用项目内的同源转发，兼容不支持浏览器跨域预检的本地接口。转发只允许本机访问固定 `127.0.0.1:11434` 的聊天和模型列表，不开放任意地址、模型管理或云端模型调用。远程发布的静态网站、手机访问电脑网址和桌面宿主不使用这条本地 Vite 转发；这些环境仍需各自可用的本地接口连接方式。

### 新核心的隔离试用与验证

保持默认设置会继续使用原运行入口。需要试用新核心时，可在单独的开发进程设置 `VITE_CORE2_ENABLED=true` 后启动，再建立新旅程；不要把旧版存档导入新核心。开关只决定入口，不会把两个运行时的游戏状态同时写入。关闭该开关可回到旧入口，新核心的数据不会因此被清除。

`pnpm test:core2-recall` 默认运行已审阅冻结的160条独立来源场景，检查召回、知情权限和原文证据；这是合成资料测试，不等于真实模型台词质量或真实后端延迟验收。DeepSeek原测试集保留，可用 `--legacy-cases` 查看其跨组重叠审计失败；`--turns=20 --slice` 仅作合同切片，不能冒充完整验收。长期测试入口目前仍标注简化账本负载，不代表完整游戏规模压力验证。

## 项目结构

```text
components/  前端组件、布局和各游戏系统面板
data/        内置菜单、世界书、提示词、原著资料和系统预设
hooks/       顶层游戏状态、主剧情流程、记忆、蒸汽鸟报和存档工作流
models/      TypeScript 数据模型与归一化逻辑
prompts/     CoT 与系统提示词模块
public/      随包发布的公开世界书和图鉴预设资源
services/    AI 请求、存档、剧情推进、记忆压缩、检索等服务层
styles/      Tailwind、主题变量和全局样式
utils/       变量执行、路径解析、背包、相册、世界书等工具函数
```

## v1.5.0 交付边界

本里程碑交付的是“正式提瓦特运行时与冒险者手账视觉基础”，不是完整游戏系统终点。

已交付：

- 温暖、生活化的冒险者手账主壳与日式西幻视觉。
- 六国新游戏向导与自定义旅行者。
- 唯一 Teyvat / schema 2 状态根、`NarrativeTurn`、领域命令与原子结算 / 恢复。
- 历史存档只读识别和显式单向迁移；导入 JSON（压缩包取原 `save.json`）会按原字节先行备份，旧 sidecar 仅参与迁移输入而不改写备份，歧义不会写入，事务失败不会改变 saves / 目录 / 资源 / 增量四库。
- API 设置面板。
- 世界书管理。
- 变量系统与变量管理。
- 伙伴、背包、装备、记忆、蒸汽鸟报、剧情编织、图鉴、相册等主要系统骨架。
- 七地区地图展示、神像激活与传送，以及无伤害数值的场面元素附着 / 反应记录。

后续里程碑（尚未交付）：

- 地区节点探索、委托与随机事件循环。
- 基于正文证据的轻量遭遇、元素互动与奖励结算，不建设复杂数值战斗。
- 伙伴同行、关系与天赋成长的叙事反馈闭环。

明确不规划：复杂武器强化、圣遗物词条 / 套装养成、四人战斗编成、祈愿、保底与抽取记录系统。
