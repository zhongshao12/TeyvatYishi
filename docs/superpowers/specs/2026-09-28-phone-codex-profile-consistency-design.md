# 手机、图鉴与人物档案一致性设计

日期：2026-09-28

## 意图与边界

这是已确认四批改造中的第二批。目标是让手机互动、人物资料与图鉴可靠地延续已发生的旅程：朋友圈评论完整且符合角色所知，派蒙等人的来信不泄漏系统格式；玩家能给联系人备注、编辑旅人档案、归档并恢复同伴；人物外貌资料结构化且来源明确；地点、角色、术语图鉴可以切换并看到对应内容。

保留现有存档根、NPC 稳定 ID、手机会话 ID 与角色原名。只扩展现有领域模型和页面，不另建第二套人物数据库。第三批蒙德至纳塔主线与第四批斗地主不在本批实施。

## 方案选择

1. **推荐：在现有领域对象上增加小型结构化字段与纯变换函数。** 手机备注不改 NPC 姓名；外貌来源与归档状态随 NPC 存档；图鉴按现有分类 slug 过滤；UI 读取同一份数据。迁移面小，能够逐项测试。
2. 新建统一人物资料库，再让手机、同伴、图鉴同步到它。长期可能更规整，但需要大量双向同步与旧档迁移，当前串档和性能风险更高。
3. 仅在界面增加按钮、文字过滤和提示词。改动最少，却无法保证读档后备注、归档、外貌来源及来信清理仍一致。

采用方案 1；不为此批引入新依赖或大规模状态重构。

## 手机：评论、来信与备注

- `CourierContact` 增加可选的玩家备注。列表、聊天标题和联系人详情优先显示备注，同时保留角色原名供模型生成、提及识别、头像查找和存档身份匹配；删除备注后立即恢复原名。备注按联系人 ID 更新，不按同名文本广播。
- 朋友圈仍只允许当前手机联系人中好感度超过生死挚友阈值的角色评论，每条最多三人。评论 API 请求使用角色性格、称呼、已知共同经历和动态正文；输出上限与请求 token 预算匹配。返回空白、模板泄漏、明显断句或超长时进行一次独立重试；仍失败则标记该角色评论失败并提供重试入口，不把半句话当作成功写入。每个目标沿用现有 session/post/revision 守卫，编辑或删除动态后旧请求不得回填。玩家不能通过评论获知角色不知道的其他人私事。
- 手机来信的事件种子只提供事件事实，不得把 `<time_format>`、`time:`、`scene:` 或系统标签当作角色台词。入口清理模板与控制字段，输出再做泄漏校验；失败时使用已清理事实的角色化本地兜底或显式重试，不回显原始种子。显示时间继续读取游戏时钟，而非模型自由生成的时间段。

## 旅人档案、关系图与同伴归档

- 旅人档案增加显式“编辑／保存／取消”模式。可编辑姓名、别名、性别、年龄、身高、生日、身份、外貌、性格、背景等玩家基础资料；保留头像编辑。姓名不能为空，年龄和身高须通过格式校验；取消不改存档，保存走现有旅人状态和存档通路。元素觉醒、等级、背包和回合时间等派生/结算数据不在此处自由改写。玩家更名后私密档案中引用 `player` 的首次对象仍按当前姓名显示。
- 将以玩家为中心的关系图与最近好感度变化移入旅人档案，复用现有 `RelationshipGraphPanel` 和结算批次，不再维护第二套图数据。点击节点可跳转对应同伴档案；最近事件继续显示实际增量、绝对设置与原因，不从当前好感度反推假历史。
- 同伴页原关系图入口换成“已归档”。NPC 记录增加可选归档状态与归档前阶位；归档不删除角色、不改变身份与历史记忆，角色从活跃同伴/路人列表隐藏、从同行队伍退出并停止作为活跃同伴注入。手机联系人不因归档自动删除。恢复按保存的阶位回到列表，但不自动重新加入队伍。归档与恢复按稳定 NPC ID，旧档默认未归档。

## 人物外貌、常用穿着与成年私密字段

- NPC 外貌档案固定提供头发发色、眼眸颜色、身高、体重、三围的结构化展示。未知字段显示“未记录”；AI 可在用户触发补全时填空，生成值标记“AI 推测”并可手动修改，绝不覆盖既有明确资料。姓名、角色 ID、年龄确认不能由该补全请求改写。数值需符合基本格式与合理范围，失败不写入半份资料。
- 三围及内衣字段仅对**独立确认成年**的女性角色开放。未成年、年龄未知、受保护对象均不生成、不显示其私密信息；不能凭缺少未成年线索或模型自称“成年”通过门禁。内衣信息属于私密档案，只由明确剧情证据或手动编辑写入，不让 AI 无依据编造。
- 现有 `穿着` 的 UI 名称改为“常用穿着”。普通回合的临时换装不覆盖常用值；仅玩家手动修改或正文明确说明“今后常穿／固定改为”等持久变化时更新。保留临时穿着在事件记忆中，不把它误当角色基准造型。外貌推测与手动值的来源随存档保存。

## 提瓦特图鉴

- 修复当前分类按钮使用中文标签、筛选却比较英文 slug 的不一致：状态存 slug，显示中文标签。地点、角色、术语切换后只展示该分类；切换分类时清理不属于新分类的选中条目，并自动选中当前列表首项。现有内置图鉴包已经提供这三类资料，本批修好筛选与内容加载反馈，不新增虚构条目。
- 区分“此分类尚无条目”和“搜索无匹配”，不拿上一分类的详情充数。已锁定条目遵守既有解锁状态，不因切换分类泄漏正文。数据来源继续使用现有 `ArchiveCodex`；本批不凭空生成原著条目。

## 一致性与验收

1. 朋友圈三位候选分别成功、失败、重试以及编辑/删除并发时，评论完整、身份正确、不串到旧版本；失败可见且不把半句落盘。
2. 含 `<time_format>`、`time:`、`scene:` 的种子不出现在派蒙来信或其他角色短信；游戏时间显示仍与系统时钟一致。
3. 联系人备注、旅人档案编辑、同伴归档/恢复和外貌来源经存读档后保持一致；改名与同名 NPC 不串资料；归档角色不自动返队。
4. 关系图在旅人档案中仍能以主角为中心、打开 NPC；最近好感变化来自结算批次，同伴页提供可恢复归档。
5. AI 仅补全空白且标注“AI 推测”，不覆盖手动/原著资料；年龄未知时三围与内衣不生成、不显示；常用穿着不随临时换装漂移。
6. 图鉴地点、角色、术语按钮各自展示对应条目；空分类和无搜索结果有明确提示；已锁定内容不泄漏。

实施按手机评论与来信、手机备注、旅人档案与关系图、同伴归档与外貌、图鉴分类逐项编写失败测试再修复；每项跑定向回归，最后运行全量测试、类型检查、Lint 与生产构建。
