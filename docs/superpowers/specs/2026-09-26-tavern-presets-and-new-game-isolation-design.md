# 移除内置酒馆预设与新开局存档隔离

日期：2026-09-26

## 目标与边界

玩家希望设置里不再出现任何内置酒馆预设，并修复两个同名角色分别开局后数据混在一起的问题。成功标准是：玩家导入的酒馆预设仍可选择、编辑和保存；连续创建两个同名角色时，第二局不继承第一局的任何每局进度；分别保存并按存档 ID 读取时，各自恢复自己的数据。

本次不把“纪年”改成抽奖，也不加入积分、保底或技能奖励。原生提示词规则、开局预设、世界书、图鉴和原著剧情资源不属于要移除的“内置酒馆预设”。API 设置与玩家导入的酒馆预设继续作为全局设置共享。

## 现状与根因

`data/builtinPresets` 注册了一个原生酒馆预设及三个随包提供的 V2 酒馆预设；三个 JSON 资源位于 `public/data/builtin-presets`。设置页、上下文快照和正文提示词组装会查询这些注册项。旧设置可能将其 ID 记录为当前选择。

新开局 `App.tsx` 的 `handleStartGame` 以 `current` 游戏状态为起点，只覆盖聊天、NPC、手机等部分切片。`applyLegacyGameStateOverrides` 对未传入的切片保持原值，因此背包、任务、相册、地图探索等可能从上一局流入下一局。存档树已使用随机 `rootId`/`nodeId`，本地存档读取按数字 ID，并非按角色姓名检索；修复目标是新局状态来源，而非禁止同名。

## 设计

### 内置酒馆预设清退

从可选酒馆预设列表和运行时加载路径移除原生内置项及三个打包的 V2 项，并移除对应静态 JSON 资源。设置页只列出玩家导入的 V2 酒馆预设；现有导入、编辑、保存和切换行为保留。旧 V1 导入迁移路径如仍被使用，只保留它向玩家自有 V2 预设的迁移，不再指向内置项。

初始化或更新全局游戏设置时，若 `currentStPresetId` 或 `currentStPresetIdV2` 指向已清退的内置 ID，则归一为 `null`；当前存档读取流程不载入酒馆设置。玩家导入的预设列表不删除，也不因与旧内置项同名而过滤。总开关不因清退自动切换；未选中预设时，正文仅使用游戏原生提示词模块。不得把旧内置内容复制进玩家预设。

### 新开局隔离

新开局先构建 `createEmptyTeyvatGameState()`，再注入本次创建的旅行者、世界、初始 NPC 与按本次开局档案重建的剧情编织。独立初始化对话、记忆、背包、任务、相册、地图、原著轨道、手机、世界树、蒸汽鸟报、后台队列以及叙事运行状态。图鉴沿用当前全局图鉴目录的内置与自建内容定义，但将 `unlockedEntryIds`、条目运行时解锁状态及解锁备注清空；它们属于每局进度，不能带入新局。

切换新局时继续使旧会话失效、清空活跃存档树元信息和恢复任务标记；第一次保存时产生新的存档树根。存档读取继续按 ID/树节点，不按角色姓名。已有存档不自动改写或猜测清理，因为无法可靠判断历史混入数据的归属。

## 错误处理与验证

移除内置 JSON 后，任何旧内置 ID 都只能归一为空选择，不触发资源请求；玩家导入的预设继续按原流程加载。若本次开局的原著剧情资源加载失败，保留当前明确的错误提示/回退机制，但回退只能使用安全的本局基线，不能复制上一局运行时剧情进度。

测试先行：

1. 给“旧内置选择清空、同名用户导入预设保留、正文不加载内置资源”添加失败用例，再清退注册与调用。
2. 给“带有背包、任务、相册、地图、图鉴解锁等旧进度的状态 → 同名新开局 → 全部每局进度归零”添加失败用例，再改新局构造。
3. 验证两个同名新局得到不同存档树根，分别保存/读取时数据不互串；回归现有导入预设、存档、剧情开局和主回合测试。

## 不做的事

不批量重写历史存档；不删除玩家导入预设；不改变全局 API 设置；不修改“纪年”入口；不新增抽奖系统。
