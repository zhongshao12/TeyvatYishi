# 逐回合记忆完整性与世界树压缩设计

日期：2026-10-11。状态：用户已批准方案方向；本文待用户审阅，尚未进入实施计划或产品代码修改。

## 1. 目标与范围

用户要求修复：世界树缺少一键压缩；分层记忆丢失回合与自动压缩异常；批量重建没有逐回合总结；重建弹窗被记忆面板遮挡。用户已确认：每个完整回合独立生成摘要，再按各层阈值压缩；保留原文、来源回合与世界时刻；只替换所选范围；失败、取消、切档不覆盖原记忆。一键压缩复用同一规则，并接受逐回合调用增加费用。

本批属于架构级边界迁移：沿用四层记忆、世界树、现有记忆 API 与存档服务，新增来源与提交边界，不重写整套回合系统。不包含图鉴内容、相册风格、供应商接入、NPC 私密档案或手机行为改造。前一批手机照片按钮修复独立保留。

成功标准：所选范围每个可恢复的完整回合都有独立摘要与可查看原文；压缩后仍能追溯每个来源回合；局部重建不清空范围外资料；任何异步结果都不能写进另一个存档；弹窗可以正常点击和键盘操作。

## 2. 已确认的代码问题与限制

- `services/memoryRebuild.ts` 将一批回合一起发送，仅得到一条短期摘要。批大小默认为 15，不代表已生成 15 条摘要。
- 重建的短期→中期和中期→长期共用 `getThreshold`，调用方只传即时→短期阈值。
- 重建 staging 从空记忆开始，提交时整片替换，所选局部范围外的记忆没有合并保留。
- `addImmediateMemory` 在压缩前执行 `slice(-50)`，可能丢弃尚未压缩的积压条目。
- 重建协调器捕获旧状态后等待模型，提交与失败草稿路径缺少任务起始会话和来源校验。
- 重建 `Modal` 位于 App 内且为 z-50，`SystemDrawer` 同为 z-50 但 portal 到 body；仅调整 JSX 顺序不足以保障覆盖。
- 当前自动压缩已有独立阈值和失败草稿。不能将所有“未压缩”归因于一个缺陷：未启用 API、未达阈值、失败待重试和来源变动都需分别说明。
- 已有世界树覆盖校验保守保护原始证据；不能为了减少条目数而取消它。

已实际删除、且历史聊天或备份中也没有的原文无法保证恢复。UI 必须列出缺失回合，不声称已经重建它们。

## 3. 方案取舍

采用用户选定的“逐回合摘要＋统一分层整理”。相比只调整批大小为 1，它还解决来源、局部替换和异步提交问题。相比重建全新事件数据库，本方案保留既有数组及存档字段，新增可选来源字段，迁移风险较小。

批大小继续作为进度分组参数，不再控制一个摘要包含多少回合。默认顺序调用模型，不额外引入并发请求。每个完整回合至少一次摘要请求，分层晋升和配置内的重试另计；执行前显示可恢复回合数与基础调用次数，不宣称精确价格。

## 4. 边界与数据模型

### 4.1 来源条目

内部使用具备稳定 ID、层级、正文、实际来源回合列表、来源消息 ID、来源档案 ID、世界时刻范围的条目。回合列表必须保留缺口，例如 `[3, 5]` 不能被冒充为完整的 3–5 回合。

继续用四层文字数组及同索引 ID；新增可选 `来源回合` 和 `生成文本指纹` 映射，配合现有 `来源时刻`。指纹在系统生成条目时保存，手动编辑不刷新生成指纹，文本不匹配时按玩家编辑保护。旧记录优先与精确关联的世界树文本核对，无法证明未被编辑则保留。同索引 ID、回合映射及世界树来源必须一致。旧记录没有可验证来源时保持未定位，不从文本模糊匹配后删除。

每个重建回合保留完整玩家输入、有效正文及消息 ID，原文作为世界树可展开来源。摘要单独存储，不以摘要覆盖聊天正文。新回合记录结算后的 `WorldMoment`；历史重建优先使用消息上保存的时刻，其次使用可精确定位到该回合的既有来源时刻。无法验证的日期、时刻、天气、地点和旅行天数保持 null 并显示“未记录”，不使用电脑时间或当前世界状态补写。

摘要晋升时保留实际来源回合并集和边界世界时刻。摘要不被当成完整原文；来源保留与模型上下文投递仍是两件事，不将全部历史原文塞进模型。

### 4.2 共享整理服务

从现有记忆压缩代码逐步提取来源选择、阈值读取、晋升与来源核验逻辑，供自动压缩、批量重建和世界树一键压缩调用。避免三份分别实现的压缩循环。

阈值明确区分：即时→短期、短期→中期、中期→长期；沿用现有设置值和缺失字段的默认/迁移规则，不改玩家已经配置的数值。重建已为每回合生成短期摘要，不再把即时→短期阈值错误用于中长期晋升。未达阈值的剩余条目保留在原层。

### 4.3 提交协调器

开始时绑定任务 ID、存档会话 ID、存档线身份、所选消息及将处理来源的指纹。提交读取 live root，不使用请求开始前捕获的整份状态。

仅在会话一致、未取消、来源未修改且全部必需请求成功时，构造一次记忆＋世界树更新。无关的新增资料和编辑保留；处理范围内的来源被编辑、删除、重掷或正文改变则拒绝旧结果并说明原因，不能自动复活删除条目。

在 await 之后、UI 更新之前、失败草稿写入之前、保存任务入队之前均校验身份。保存通过既有跟踪队列持有原任务的存档身份，不能在落盘时重新读取另一个存档的身份。发生持久化失败时显示“页面已更新，保存失败”，保留可重试结果，不声称保存成功。

## 5. 批量重建流程

1. 提取所选范围中完整的玩家输入＋已落地正文。排除正在流式生成、失败或无正文消息；同一回合多次重掷采用当前有效最后一份正文，显示重复或缺失诊断。
2. 按回合顺序独立总结；进度按成功回合推进，显示当前回合、分层阶段和失败来源。每个回合的成功摘要与原文先留在任务 staging。
3. 按独立阈值晋升短期、中期记忆，形成可追溯摘要和世界树档案。
4. 请求失败即暂停。已经成功的逐回合摘要不重复请求；重试从失败的回合或晋升步骤继续。API 开启时，本地 fallback 不可被当作成功重建结果。
5. 所有步骤完成且身份校验通过后，再进行范围合并和保存。直到这一刻，原有游戏记忆不被 staging 取代。

局部替换规则：仅替换来源明确且全部落在所选范围内的旧条目。范围外、跨范围、来源未知或玩家手工编辑的条目保留。跨范围旧摘要不拆成臆造的两份；界面说明“部分旧摘要因跨范围或来源未知保留”，不承诺条目数一定下降。对应未处理失败草稿也保留。新原文和摘要依据稳定来源身份去重；重复提交不产生第二份结果。

失败草稿可单独追加到原任务存档，保留完整失败材料、来源、错误及重试身份；“原记忆不覆盖”不等于隐藏失败。切档或取消后的迟到响应不得写入任何当前档案。关闭弹窗会取消本重建，不中止其它任务；任务控制器独立于主回合。

## 6. 自动压缩与世界树一键压缩

### 6.1 自动压缩

取消压缩前对未安全归档即时来源的硬截断。大量积压保留，不新增发送前硬上限，也不扩大既有模型召回窗口。

每个已成功结算回合按既有入口检查阈值；具备条件时整理所有可处理完整批次。模型失败保留原层来源与失败材料，标记待重试，不将失败的 fallback 当作已覆盖来源推进下一层；同一失败来源在手动重试前不被后续回合反复自动请求，失败草稿按来源身份与材料指纹去重。未配置、未达阈值、暂缓（来源改变）与模型失败分别反馈，避免显示空泛“整理完成”。重建与手动压缩运行时，同一存档的整理任务互斥；主剧情仍可继续，若修改被处理来源则旧整理安全拒绝提交。

API 关闭时沿用本地摘要模式，但必须保留原始可追溯证据，仍然执行覆盖校验；界面清楚标明本地整理，不冒充模型总结。

### 6.2 一键压缩

世界树页新增“一键压缩”、进度、取消及结果说明。使用同一套阈值、记忆 API、来源校验及提交协调器，不绕开设置强行压缩不足一个完整批次的条目。

候选包含四层记忆绑定的来源，以及世界树中可验证、尚未被覆盖的 short/medium 档案；按稳定 ID 去重，不能同时从两条入口处理同一来源。与四层数组绑定的条目同步更新；仅在世界树的条目只更新其世界树摘要。

pending、缺少完整来源身份、现有原文锚点 refined 以及已经被验证覆盖的来源不进入盲目再压缩。没有合格批次时不调用模型，并明确显示原因。一键压缩不等于一键清空原文或重新生成全部记忆。

继续使用 `hasVerifiedIrminsulCoverage` 与 `promoteIrminsulEntry` 的验证边界。无法证明摘要覆盖全部事实时，保留原档与新摘要并说明“原文保留”；不因为模型声称已涵盖、包含所有回合号或满足条数门限就删除原文。

## 7. UI 与任务生命周期

- 重建弹窗 portal 到 body，使用明确高于系统面板的嵌套弹窗层级，复用现有 Modal 的焦点、Esc 及恢复逻辑。默认普通弹窗行为保持不变，不全局提高所有页面层级。
- 记忆页仍留在弹窗下方；Esc 只关闭栈顶，关闭后焦点回到批量重建入口。小屏中弹窗内容独立滚动，开始、取消、重试按钮可达。
- 说明文案改为“逐回合总结、仅替换所选可定位来源”，移除当前“整份四层记忆替换”描述。
- UI 显示缺失回合、不可定位旧条目、自动压缩状态和模型调用基础数量。无需伪造已丢失资料。
- 同一存档不能并行启动两次整理；连点开始不创建重复任务。切档、重开和卸载取消任务并清理监听器。
- 重试只对应原任务；更换范围或切档必须创建新任务，不借用旧 staging。

## 8. 验收与验证

实施先建立失败测试，再修改产品代码；不删除既有业务断言来获得通过。

- 15 个完整回合产生 15 条独立摘要来源；缺失 4、7 回合明确提示，不伪造连续覆盖。
- 每回合的关键事件、物品结果、承诺与未完事项出现在各自模型输入；不能用第一批摘要覆盖后续摘要。
- 使用不同的三层阈值，逐层晋升次数与剩余条目正确；多批次积压可以整理；超过 50 条仍能保留所有未经安全归档来源。
- 重建 10–20 回合后保留 1–9、21 之后、跨范围和不可定位资料；ID、来源映射、失败草稿与世界树一致。
- 第 8 回合失败后重试不再次请求已成功的 1–7；晋升失败不再次请求已完成的逐回合摘要。
- 模型完成前切档、取消、重开、重掷、编辑处理来源、删除档案：均拒绝旧提交；无关编辑和追加可以保留合并。
- 当前存档保存失败显示正确状态，不能把原任务结果写到后来打开的存档；JSON 保存/恢复后来源完整，重复提交幂等。
- 自动、一键与重建共用规则：失败原文保留、缺少覆盖不删除、pending 不参与召回、没有候选不调用模型。
- React 交互测试覆盖连点、逐回合进度、重试与取消；真实浏览器小屏/桌面合成数据验收覆盖层、点击、滚动、Esc 与焦点恢复，不操作玩家真实存档。
- 最终执行 TypeScript、关联测试、完整单测、回归脚本、构建、资源与体积门禁。纯 TypeScript/UI 修改不宣称验证了 Rust 或真实供应商效果。
