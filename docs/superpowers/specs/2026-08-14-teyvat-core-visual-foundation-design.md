# 旅行者纪事：提瓦特语义内核与视觉基座设计

> 日期：2026-08-14  
> 状态：已获用户逐节批准  
> 对应里程碑：完整原神化第 1 阶段  
> 后续阶段：旅行与探索、战斗与元素反应、角色养成与队伍、剧情融合

## 1. 背景

当前仓库已经完成了部分原神化工作：菜单、主题、六国开局、角色资料、部分剧情数据和展示文案已经改为提瓦特内容。但是改造尚未形成语义闭环：

- 运行时模型仍大量使用 `命途ID`、`命途进度`、`战技`、`lightcone`、`手机`、`忆庭` 等崩铁概念。
- `models/world.ts` 等核心路径仍存在黑塔空间站等旧默认值。
- 开局、变量、生图、新闻及回合组装提示词仍含崩铁式场景、语气和示例。
- 文档声称 M0–M7 已完成，但代码版本、运行时语义和验收状态并不一致。
- 现有“旧 ID + 新显示名”方式会把错误抽象继续带入未来的地图、战斗和养成系统。

因此，本阶段不再做展示层换皮，而是采用边界迁移式重构：旧数据只在兼容边界被读取和转换，新运行时只使用提瓦特领域模型。

## 2. 已确认的产品决策

### 2.1 产品目标

项目最终将成为一套完整游戏化的原神同人叙事系统，并按以下里程碑推进：

1. 提瓦特语义内核与视觉基座。
2. 旅行与探索。
3. 战斗与元素反应。
4. 角色养成与四人队伍。
5. 剧情融合与世界演化。

本规格只覆盖第 1 项。

### 2.2 玩家身份

- 玩家是自定义旅行者。
- 空与荧作为两个独立的原著角色存在，可相遇、同行或进入不同剧情线。
- 空、荧不取代玩家，也不能与玩家档案共用身份字段。

### 2.3 原著主线

- 魔神任务提供人物、时间和事件锚点。
- 玩家可以改变事件过程与结果。
- 系统必须记录偏离发生的证据、影响范围、后续后果与可能的回归路径。
- 原著轨道不能强行覆盖已经成立的玩家事实。

### 2.4 视觉方向

全局采用“冒险者手账”风格：暖羊皮、水彩地区背景、皮革和木质边框、生活化委托感。战斗、深渊和元素回响可进入局部暗色或魔导书仪式态，但仍属于同一套设计系统。

## 3. 范围

### 3.1 本阶段必须交付

- 唯一的新运行时状态 `TeyvatGameState`。
- 提瓦特领域模型及归一化入口。
- 旧存档、云存档和导入包的识别、备份、迁移与回滚。
- 主剧情、变量、任务、新闻、信使、世界树、图鉴及生图工作流的提瓦特协议。
- 六国开局与自定义旅行者档案。
- 可偏离原著轨道的数据结构。
- 冒险者手账设计令牌、核心布局、地区背景和移动端规则。
- 运行时旧术语门禁、测试矩阵与文档同步。

### 3.2 本阶段不实现

- 可操作的大地图、传送锚点、七天神像和探索度结算。
- 元素附着、元素反应、敌人 AI 和完整战斗数值。
- 角色等级、突破、命座、武器强化和圣遗物词条强化。
- 四人队伍切换。
- 祈愿或抽卡系统。

本阶段可以定义这些系统需要的稳定 ID 和模块接口，但不得实现半套玩法。

## 4. 总体架构

### 4.1 单向兼容边界

数据流固定为：

```text
旧 IndexedDB / 云存档 / 导入包
            ↓
兼容识别与原始备份
            ↓
迁移、归一化与完整校验
            ↓
TeyvatGameState
            ↓
提瓦特领域服务、UI、提示词与存档
```

硬性约束：

1. 旧字段只能在 `compat/legacy-hsr` 或等价兼容目录中读取。
2. 新运行时不得重新写出命途、光锥、手机、忆庭等旧字段。
3. 新功能只能依赖提瓦特模型，不得引用兼容层类型。
4. 迁移必须是原子的；任何关键字段无法归一化时，整体失败并保留原档。
5. 旧档迁移前必须保存可恢复的原始副本。

### 4.2 复用现有能力

以下成熟引擎继续保留，但改为通过提瓦特领域接口读写：

- 主剧情发送与流式渲染。
- 变量结算与正文事实抽取。
- 三层记忆压缩和角色同行记忆。
- 剧情编织与冲突检测。
- 工作流恢复日志。
- 本地存档树、云备份和桌面镜像。
- 新闻、通讯和生图持久化队列。

## 5. 提瓦特领域模型

### 5.1 角色与力量

核心类型：

- `TravelerProfile`：玩家自定义旅行者档案。
- `CanonicalTraveler`：空、荧等原著旅行者身份，独立于玩家。
- `ElementId`：仅包含风、岩、雷、草、水、火、冰七元素。
- `PowerSource`：神之眼、旅行者共鸣、仙力、魔神权能、深渊力量、其他来源。
- `ElementalAttunement`：元素亲和、精通、解锁状态和来源。
- `Talent`：普通攻击、元素战技、元素爆发、固有天赋。

`ElementId` 与 `PowerSource` 必须分开。深渊不是第八元素，神之眼也不能简单描述为七执政直接授予。

现有“微光、共鸣、精通、神选、权柄”不得继续冒充原作世界观层级。可保留可迁移的游戏成长数值，但显示与规则必须明确属于本项目的玩法进度，而非原著事实。

### 5.2 世界与资产

- `TeyvatWorld`：当前日期、时间、地区、地点、天气、公共事件。
- `RegionState`：为后续探索度、锚点、神像、声望和采集状态提供稳定边界。
- `Inventory`：武器、圣遗物、料理、材料、小道具、任务物品和摆设。
- `ArtifactLoadout`：生之花、死之羽、时之沙、空之杯、理之冠五部位。
- 物品稀有度统一为一至五星；颜色是展示属性，不能代替真实星级。
- NPC 统一记录身份、阵营、元素/力量来源、好感、同行状态和共同经历。

### 5.3 剧情与任务

- `Quest` 类型包括魔神任务、传说任务、世界任务、每日委托、邀约和活动任务。
- `CanonTrack` 保存原著事件锚点和当前推进段。
- `CanonDeviation` 保存偏离类型、正文证据、发生回合、影响角色、世界影响、阻断的后续事件和回归可能。
- 玩家已经改变的事实优先于原著未来段落。
- 原著资料只校准设定、角色边界和可能事件，不能自动写成玩家已知或当前已发生事实。

### 5.4 延伸系统

- `CourierSystem`：私信、信件、公告、群组往来和主动来信。
- `SteambirdNews`：只处理可公开传播的已提交世界事件。
- `IrminsulMemory`：世界树记忆的归档和检索。
- `ArchiveCodex`：角色、地点、组织、术语、事件、武器、圣遗物、料理和敌人资料。

## 6. 存档迁移策略

### 6.1 存档分类

加载时必须先判断：

1. 新提瓦特存档：直接归一化为当前 schema。
2. 当前仓库产生的“部分原神化存档”：根据已知旧 ID 映射到新模型。
3. 真正的崩铁旧宇宙存档：不自动转换为提瓦特剧情，只提供只读查看和导出。
4. 未知或损坏存档：隔离并报告问题，不覆盖原数据。

### 6.2 部分原神化存档

当前分支已把部分旧 ID 当作元素使用，例如 `elation` 显示为风、`preservation` 显示为岩。此类存档可按当前版本中已经成立的显示语义确定性迁移，并在迁移报告中记录来源字段。

典型映射：

- 旧元素代号 → 新 `ElementId`。
- `lightcone` 且展示语义已经是圣遗物 → `artifact`。
- `手机` 状态 → `CourierSystem`。
- `忆庭` 归档 → `IrminsulMemory`。
- 旧品质色名 → 对应真实星级；无法确定时进入待确认迁移项，不猜测。

### 6.3 真正崩铁存档

不得把三月七、黑塔、仙舟或匹诺康尼等人物与剧情自动改写成提瓦特对象。此类存档只能：

- 原样导出。
- 在旧宇宙只读查看器中打开。
- 由用户新建提瓦特存档时手动摘录少量通用玩家设定；剧情事实不迁移。

### 6.4 原子性

- 迁移生成临时结果。
- 临时结果通过 schema、引用完整性和领域不变量验证后，才写入新存档树。
- 写入成功前不得删除或修改原节点。
- 云存档包使用新的 universe 与 schema 标记，避免新旧包混传。

## 7. 冒险者手账视觉系统

### 7.1 视觉语言

- 主材质：暖羊皮、皮革、木质、古铜金属。
- 主色：皮革棕、羊皮纸米色、旅行青绿、古铜金。
- 辅助色：地区元素色、魔法紫、危机赤褐。
- 标题使用开源宋体，正文使用清晰的开源或系统黑体。
- 不打包原神官方字体、立绘、截图、图标、音频或 Logo。

### 7.2 桌面布局

保留现有三栏信息架构，但重构为：

1. 左侧“人物书签”：旅行者、元素、队伍与即时状态。
2. 中央“正文页”：叙事、角色名板、行动选项和当前任务。
3. 右侧“索引签”：任务、纪行、背包、信使、图鉴和世界树。

所有按钮、弹窗、输入框、提示条和系统面板必须使用统一设计令牌，而不是各自写死颜色和材质。

### 7.3 背景系统

背景由四层组成：

1. 每个地区一组原创或授权水彩远景。
2. 时间、天气和危机状态的动态色层。
3. 保证正文对比度的统一半透明遮罩。
4. 可关闭的粒子、视差和翻页动画。

地区只改变远景、纹样和强调色，不改变全局组件结构。深渊、战斗和元素回响使用暗色危机态或局部魔导书仪式态。

### 7.4 移动端与可访问性

- 正文单栏优先。
- 人物与系统入口进入底部书签栏或抽屉。
- 尊重安全区、触控尺寸、键盘导航和屏幕阅读器标签。
- 支持“减少动态效果”和低性能模式。
- 背景必须经过对比度遮罩，不得影响长文本阅读。

### 7.5 素材合规

- 背景、纹样和角色占位图使用原创生成、用户授权或许可兼容素材。
- 每项资产记录来源、生成方式、作者、许可证和用途。
- 不把“Genshin-like”作为对外分发素材的唯一描述；资产提示词应描述可观察的原创风格特征。

## 8. 回合数据流

一次玩家行动按以下顺序处理：

1. 接收玩家行动。
2. 冻结回合快照：地点、时间、在场角色、任务、战斗和当前原著轨道。
3. 组装提瓦特上下文：已成立事实、记忆、图鉴、世界书、原著锚点与偏离记录。
4. 主叙事模型返回结构化 `NarrativeTurn`。
5. 校验结构、术语、设定边界、玩家代写和角色信息域。
6. 变量模型或事实提取器生成领域命令候选。
7. 各领域验证器按白名单验证命令，并分析新的原著偏离。
8. 所有同步变化生成一个 `NextState` 并原子提交。
9. 蒸汽鸟报、信使、世界树记忆和生图队列读取已提交事实异步运行。
10. 写入恢复日志和自动存档。

### 8.1 叙事协议

概念结构：

```ts
interface NarrativeTurn {
  body: StoryBlock[];
  choices: PlayerChoice[];
  factCandidates: FactCandidate[];
  continuation: ContinuationSummary;
}
```

新协议不要求模型输出可见的 `<thinking>` 思维链。规划信息必须是短小、结构化、可验证的承接摘要。

### 8.2 状态写入规则

- 模型输出不能直接修改 `TeyvatGameState`。
- 每个候选事实必须能在本回合正文或明确系统操作中找到证据。
- 角色、任务、背包、元素、世界等领域分别维护可写字段白名单。
- AI 不得创建未知根字段或覆盖完整领域对象。
- 未公开资料不得进入新闻或不知情 NPC 的台词。

## 9. 错误处理与恢复

### 9.1 主模型失败

- 本回合状态不变。
- 保留玩家输入。
- 允许使用相同模型重试或切换模型。

### 9.2 领域结算失败

- 正文可以保存为“待结算回合”，但不写入任何部分变量。
- 恢复日志记录失败阶段、输入快照和待处理命令。
- 修复后从结算阶段继续，不重新生成正文。

### 9.3 后台任务失败

- 新闻、信使、记忆压缩和生图失败不回滚核心回合。
- 失败任务进入持久化队列并独立重试。
- 多次失败后向用户显示可操作的错误信息。

### 9.4 存档失败

- 保留上一稳定节点和当前恢复日志。
- 不删除任何旧节点。
- UI 明确显示当前回合尚未安全持久化。

## 10. 提示词与内容迁移

需要逐项重建：

- 主剧情。
- 开局。
- 元素与天赋。
- 任务与可偏离原著轨道。
- 变量与领域命令。
- 蒸汽鸟报。
- 信使。
- 世界树记忆。
- 图鉴检索。
- 生图与场景快照。

验收规则：

- 运行时提示词、业务代码、默认预设和新资产元数据中，旧术语白名单外不得出现崩铁词。
- 历史文档、旧宇宙只读数据和兼容层可以出现旧术语。
- 新提示词不能要求“崩铁式语气”“舱内调度感”或类似旧世界观文风。
- 新提示词不能把七执政、神之眼、深渊和元素关系写成未经原作支持的确定事实。

## 11. 交付门禁

### Gate 0：冻结与基线

- 保存代表性测试存档。
- 建立旧术语扫描白名单。
- 记录构建、测试、包体和关键页面性能基线。

### Gate 1：领域与兼容层

- 建立 `TeyvatGameState` 和新领域模型。
- 新代码不能依赖旧模型。
- 能识别各类旧存档而不修改原数据。

### Gate 2：原子迁移

- 部分原神化存档可确定性升级。
- 真正崩铁存档只能只读或导出。
- 云存档版本隔离。
- 迁移失败恢复演练通过。

### Gate 3：工作流换芯

- 主回合、变量、剧情偏离、新闻、信使和记忆只读写新模型。
- AI 命令白名单和原子提交生效。
- 恢复日志覆盖所有关键阶段。

### Gate 4：提示词与内容

- 所有运行时提示词完成提瓦特化。
- 六国开局、角色资料、任务类型和生图规则完成校准。
- 旧术语扫描门禁生效。

### Gate 5：手账 UI 发布

- 统一设计令牌和核心组件完成。
- 地区水彩背景与危机态完成。
- 桌面、移动、减少动态效果和低性能模式验收通过。

## 12. 测试策略

### 12.1 单元测试

- 旧字段映射和 schema 识别。
- 各领域归一化函数。
- 领域命令白名单。
- `CanonDeviation` 创建和影响计算。
- 迁移原子性与失败回滚。

### 12.2 存档契约测试

- 新存档往返读写一致。
- 新存档包不包含旧字段。
- 旧存档迁移前后原始数据未被覆盖。
- 本地、云端、桌面镜像和导入包使用一致的 universe/schema 判断。

### 12.3 回合集成测试

- 六个官方地区开局均可创建、发送首回合并完成结算。
- 自定义旅行者与空、荧身份互不覆盖。
- 原著偏离可被记录并影响下一回合上下文。
- 新闻、信使、记忆和生图只能读取已提交事实。
- 各阶段失败后可以按设计恢复。

### 12.4 视觉与交互测试

- Storybook 覆盖核心组件和所有状态。
- 桌面、平板、手机视口检查。
- 六地区背景、日常态、战斗态、深渊态和元素回响态检查。
- 键盘导航、焦点、触控目标、对比度和减少动态效果检查。
- 懒加载、长会话和背景资源内存检查。

### 12.5 内容与合规审计

- 旧术语白名单扫描。
- 官方素材、字体、音频和 Logo 扫描。
- 资产来源清单完整性检查。
- 文档、版本、公告与实际实现一致性检查。

## 13. 第一里程碑退出条件

只有同时满足以下条件，才能进入“旅行与探索”里程碑：

1. 生产构建、单测、全量回归和六国开局冒烟全部通过。
2. 新存档往返读写一致，迁移失败不会覆盖原档。
3. 运行时和 AI 输出不再出现命途、光锥、黑塔等旧语义。
4. 冒险者手账 UI 在桌面与移动端完成可访问性和性能验收。
5. 背景与视觉资产均有来源记录，不包含官方受限素材。
6. 项目文档、版本说明和实际代码状态一致。

## 14. 后续里程碑接口

第一里程碑结束时，应为后续系统提供稳定边界：

- 旅行与探索：`RegionState`、地点 ID、锚点和神像注册接口。
