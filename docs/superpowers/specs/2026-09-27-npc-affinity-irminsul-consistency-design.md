# NPC 亲密结算与世界树归档一致性设计

日期：2026-09-27

## 目标与范围

这是已确认的四批改造中的第一批：修复已确认成年女性角色私密档案中首次对象名称漂移、明确事件漏记、亲密事件好感度异常，以及世界树分层压缩后重复归档。后续手机与档案、蒙德至纳塔主线、斗地主分别设计和实施，不在本批修改。

保留现有存档、回合事务、NPC 账本与世界树结构；不重建整个存档体系，不修改普通互动的任意好感变化规则，也不凭空判定未知年龄角色已成年。已有关系和非玩家对象不得被迁移覆盖。

## 已定位的问题

- `utils/variableFacts.ts` 的正文派生在匹配到性行为关键词后可发出 `ageConfirm: 'adult'`，却不填写首次对象；有姓名的句子也未充分区分玩家参与、第三方叙述、否定与回忆。`hooks/useGame/variableSettlementWorkflow.ts` 又按 NPC 名称整体过滤模型好感变化，可能错扣或漏扣。
- `utils/npcArchiveEnrichment.ts` 对未被屏蔽的女性重要 NPC 默认写入成年、初始状态和“无”，而 `utils/variableFacts.ts` 的档案写入同样可以从事件中提升年龄状态。现有“未命中未成年证据”并不等于“有成年确认”。
- 首次对象在 `models/npc.ts` 与 `models/teyvat/character.ts` 均只是自由文本，映射由 `hooks/useGameState.ts` 双向传递；玩家改名、模型写“旅行者/玩家/姓名”时无法稳定指向同一人。
- `hooks/useGame/memoryUtils.ts` 会分别生成短、中、长期世界树条目；`upsertRecallEntry` 只处理同回合精炼纪要的替换。成功向上压缩后，下层归档依然保留，长期会重复占空间、重复召回。失败草稿虽然存在，但归档清理尚不感知其状态。

## 决策与数据契约

### 1. 首次对象使用稳定身份，不使用显示名做主键

在 legacy NPC 档案和 Teyvat mature archive 增加可选的首次对象身份引用，`player` 为玩家稳定标识；同时增加来源标记 `narrative | legacy_assumed | manual`。已有 `首次性行为对象` / `firstSexualPartner` 文本字段保留为非玩家对象或旧数据兼容字段。读取 UI 时，身份引用为 `player` 就用**当前存档**旅人档案中的玩家姓名显示；不可从“旅行者”“玩家”等普通词直接反推成玩家身份，除非同一事件能确认主体。

同一条档案可保存一次明确事件的来源回合或稳定事实 ID，作为重试、恢复和重复结算的去重依据。已经记录的非玩家首次对象或用户手动填写值不被模型结果覆盖；首次对象一旦有可信确认，不因后续亲密事件改变。

老存档迁移只处理：女性、能独立确认成年、现档 `是否处女 = 否`、首次对象缺失/“无”/泛称玩家且不存在明确非玩家对象。符合条件时写 `player` 引用与 `legacy_assumed`，在经历中补一条带“旧档推定，具体回合未知”的简短记录，且只写一次。若旧档有可信正文/结算证据，优先标为 `narrative` 并保留回合；若没有，绝不伪造事件时间或细节。`是`、`未知`、不确定年龄和受保护对象不翻改。UI 可见“旧档推定”并允许手动校正。玩家改名只改变显示名，不再次迁移。

### 2. 成年与自愿事件是写入私密档案的前置条件

性行为事实不能自行产生成年确认。只有独立于本次剧情事实、可追溯的成年状态才能允许私密字段写入；原著角色不能一概由“女性”推断成年，自定义角色不能仅因没有未成年词而通过。已知受保护身份、明确未成年证据、年龄未知或非人形对象继续阻断。对旧档中来源不明的 `adult`，先核对可靠的角色资料或明确设置；无法确认时保持未知并跳过私密迁移，不能用旧默认值自证。

普通好感度也不得把受保护角色送入亲密事件自动加分路径。系统能记录普通非亲密互动，但私密档案和亲密档位仅限已确认成年、玩家与该 NPC 直接参与、正文有肯定且自愿的完成事件。否定、假设、别人之间的事件、转述、计划、明确拒绝、仅为含混暗示的句子不触发性行为档案更新。无证据时不把 `是否处女` 从“是/未知”改为“否”。

### 3. 每 NPC 每回合只结算最高亲密档位

沿用现行数值：成年自愿性行为 +30、亲吻 +5、暧昧 +3、肢体接触 +3。先把正文候选归属到明确的玩家↔NPC 事件，再按 NPC 稳定 ID 和回合取最高一档，仅形成一项确定性好感变化；同一事实在重新发送、恢复、变量重放或后台重试时不重复增加。若证据不足，该规则不接管模型的普通关系变动；若确定性事件已成功接管，只剔除同 NPC、同事件的重复模型增量，不吞掉可独立举证的冲突、帮助、违约等其他正负变化。结算回执标明实际来源和最终增量，未提交的推断不显示为已结算。

手机、正文和变量模型可能在相近时间分别生成 NPC 变化：去重键至少包含存档/回合、NPC 稳定 ID、事件类型或稳定事件 ID，不能仅凭人名或文本相似度。玩家姓名变动和 NPC 别名变化不改变去重结果。

### 4. 世界树只在上层摘要确认后清理被覆盖的下层条目

短期→中期、中期→长期的每次压缩记录明确的来源条目 ID/来源回合与目标条目 ID，使覆盖关系可验证。上层摘要成功写入、可正常检索且覆盖完整时，才将其所覆盖的低层世界树条目从活跃召回集合移出；短期和中期仍在使用的记忆层不被误删。精炼纪要仅替代其明示覆盖的同一回合纪要，不能靠标题或大致回合范围删除其它剧情。

模型失败、取消、回退摘要或待重试草稿均不能作为清理成功的依据；保留其来源与失败草稿，待重试成功后再做原子替换。旧档没有可靠来源链时不批量清理，只在可证明完整覆盖的条目组上懒迁移。重复运行压缩、读档、恢复与重试的结果相同，不再次增加副本。世界树 UI 区分活跃摘要与失败待重试内容，召回只使用被确认的活跃版本，并保持来源回合可追踪。

## 实施边界与失败处理

先为身份引用、来源标记和归档覆盖关系写纯函数与存档归一化；再接入 legacy/Teyvat 映射和回合结算；最后接入世界树提交后压缩。旧档读取遵循“先解析，不破坏原值，条件满足才补全”；无法判断身份或年龄时保留数据、显示待确认，不静默改写。私密字段的年龄校验在解析、派生、域命令提交与 UI 展示各边界保持一致，不能只依赖某一个页面过滤。世界树的归档更新与结算提交保持一致：任何一步失败都不删除旧来源，玩家可继续游戏并查看失败原因。

本批不实现 AI 自动外貌补全、不扩写主线、不改变纪年页面、不实现斗地主。那些属于已确认的后续批次。也不把“所有女性默认成年”或“所有女性已有亲密经历”作为迁移规则。

## 验收场景

1. 已确认成年女性与玩家的明确完成事件只产生一次 +30；记录的首次对象始终显示当前玩家姓名。更名、存读档、legacy/Teyvat 往返与同回合重试后不漂移、不重复。
2. 有亲吻和拥抱的同回合只取 +5；有独立负面互动时，负面变化仍可按原规则结算。第三方事件、否定、计划或角色只是旁观时不误加亲密好感，也不改首次记录。
3. 旧档中确认成年且 `否` 但首次对象缺失，补成 `legacy_assumed`，经历标注未知回合；再次加载不重复。现有非玩家对象、`是/未知`、未知年龄和受保护角色原样保留。旧档对该成人角色已有可信事件时采用 `narrative` 而非推定。
4. 未确认成年或有未成年证据的角色，无论模型是否提交 `ageConfirm: adult`，都不能写入私密档案或领取亲密事件自动加分。可追溯成人确认后再按新事件正常结算。
5. 世界树成功从低层晋升后，活跃召回没有同一事件的低/高层重复条目，来源回合仍可查；失败、取消、回退摘要时原有条目与失败草稿都保留。旧档无可靠覆盖链时不丢记录。
6. 定向单测先失败再修复；最后运行相关单测、全量测试、TypeScript、Lint 与生产构建，并手动检查两类旧档、一次失败重试、玩家更名及界面显示。
