# 手账融合：手机、朋友圈与元素天赋页面迁移设计

日期：2026-10-12。

状态：用户已确认采用预览 A「手账融合」，并于 2026-10-12 确认本设计、要求开始实施。第一批状态与请求修复已执行；正式页面迁移尚未实施。分项证据见实施报告，不以设计批准代替实际验收。

## 1. 已确认的目标与边界

本轮目标是修复 [独立整体复审报告](../../reviews/2026-10-12-independent-full-review.md) 中的 22 项问题，同时完成用户提出的页面调整：

1. 元素与天赋合为一个页面。
2. 原天赋入口所在的位置改为手机，完整迁移现有手机功能。
3. 移除左侧旅人信息栏的手机入口。
4. 参考邻舍的手机、朋友圈设置与布局，但采用本项目的「手账融合」视觉。

本轮不重写整个游戏，不改用 Vue，不引入邻舍的后端；不复制其账户、密钥、发布文件或自动发帖机制。不新增隐式模型调用，不更换存档身份，不批量覆盖角色素材、剧情资源、原有玩家数据。不顺带修改已另交执行者的亲密事件识别及年龄判定；本次审查报告里的 B08/B09 是另一套编号。

当前工作区的未提交内容须保留。设计文档、代码实施、实际游戏验收、提交、合并、推送是不同步骤；保存此设计不代表批准发布。

## 2. 视觉方向：A「手账融合」

用户原话：「手账融合的风格我很喜欢，请用这个风格」。因此不再重复让用户选择 A/B/C；B「邻舍轻盈」与 C「夜航通讯」只作为已比较的预览方案，不是本轮新增主题。

### 2.1 视觉语言

- 暖纸底色与浅色纸页承载内容；深绿色书签、选中标签和主按钮负责导航；金色细线、徽记与标题细节作点缀。
- 角色头像清晰、完整露出。正文使用深墨色；辅助信息有足够对比度，不能用低透明度金色承担主要文字。
- 标题保留手账感衬线字；输入、设置、错误信息采用易读字体。不引入额外远程字体或大面积新背景图片。
- 圆角卡片、细边框、轻阴影；背景与装饰不挡住名字、文字或按钮。裁切装饰不用于会裁掉聊天内容的容器。
- 使用现有主题变量接入预览配色，不把原型里的一套硬编码样式直接复制成第二套全局主题。其他已有主题仍应可读。

预览 A 的参考色：纸底 `#f3eee4`、纸页 `#fffdf8`、主墨色 `#302f29`、深绿 `#426453`、书签 `#243b32`、金色 `#a88a51`。实施时以现有主题变量和实际对比度验收为准。

### 2.2 预览与正式版本的区别

原型文件为 `.superpowers/brainstorm/986-1791804624/content/phone-moments-layout-v1.html`，只使用示例人物、示例对话及已有插画；不读写真实存档，不调用聊天或生图接口。

原型的风格和手机/朋友圈信息布局已选定，不代表所有示例行为都要进入产品。原型里「同伴」按钮演示通讯录跳转、示例技能和示例图片等，不替代正式同伴页、空/荧天赋或真实相册数据。正式版保留所有其他系统的入口及职责。

## 3. 页面与入口

| 当前位置 | 迁移后 | 保留内容 |
|---|---|---|
| 系统菜单「元素」 | 「元素与天赋」 | 元素共鸣、熟练度、场面元素状态、已有天赋管理 |
| 系统菜单「天赋」的位置 | 「手机」 | 私聊、群聊、联系人、朋友圈、照片、设置、失败重试 |
| 左侧旅人栏「手机」 | 移除此入口 | 身份、元素、熟练度、队伍、当前篇章仍保留 |
| 打开手机的快捷键、命令入口 | 打开新的手机系统页 | 未读数、角色目标、会话目标继续生效 |

代码中的页面身份与显示位置分开：`path` 承担合并后的元素天赋页，新增语义明确的 `phone` 页面身份；不让原 `skill` 身份暗中变成手机。现有指向天赋的内部导航应跳到合并页的天赋区域，指向手机的导航则统一到 `phone`。

未读提示移到手机菜单入口，不能因删掉左侧按钮而丢失。由其他地方打开某位联系人的操作应能准确进入其会话。此迁移不改变角色与会话的稳定 ID。

手机功能关闭时，页面显示关闭原因与设置入口；不能展示一个看似可发送、实际不会回复的输入框。页面加载失败使用已有可见的加载/重试机制。

## 4. 元素与天赋合并

一个页面内，上方为七元素选择与共鸣信息，下方为对应天赋；通用天赋单独分组。选择元素只是浏览，不等于切换当前共鸣，更不等于觉醒；切换共鸣继续走既有操作。

保留登记、编辑、升级、移除、AI 草拟等现有天赋功能。未觉醒元素不能因页面合并而获得其技能使用权限；已收藏但未可用的内容遵守现有规则。空/荧与自定义旅行者继续读取各自资料，不以原型的示例天赋覆盖。

元素区与天赋区共用当前旅行者输入及更新动作，不新增第二份旅行者状态，不复制或改变元素/天赋的存档字段。优先复用和提取现有 `PathPanel` / `SkillPanel` 内容，统一筛选状态，避免两套元素选择互相不同步。

## 5. 手机页面

### 5.1 布局

页面顶部是手机标题、设置、未读信息，下方为「消息 / 通讯录 / 朋友圈」。宽屏使用会话列表与聊天正文双栏；窄屏先看列表，点会话后看聊天并可返回。联系人和群管理长列表有独立滚动区。

聊天顶部展示真实姓名/备注、群成员信息和管理入口；中间是可滚动消息；底部保留输入与发送。玩家头像与其消息行对齐，姓名和回合标签不裁切，不同主回合之间保留虚线分隔。

发送使用 Enter，Shift+Enter 换行，中文输入法选字期间不发送。玩家正在读旧消息时只提示新增消息，不强行跳到底部；主动发送或点击「查看新消息」时回到底部。只有当前实际可见的会话才计为已读。

### 5.2 复用边界

将现有手机功能内容与外层弹窗壳分离，使新系统页使用同一份手机状态和操作。不能把带遮罩的 `CourierModal` 直接嵌进另一层系统弹窗，也不能同时挂载两份手机组件。

回信队列、角色记忆与好感结算、存档会话校验继续由现有游戏协调层管理，不搬进卡片或列表内部。界面只接收当前数据和明确动作；打开页面不自动启动新一轮模型调用。

离开手机页面不会错误取消已经提交的回信，但隐藏会话不会被自动标成已读。切档必须使旧草稿、旧生图结果和旧回信失效；同档切换会话则保留各会话草稿。关闭页面后的草稿是否保留，沿用既有行为，不新增持久保存需求。

### 5.3 必须保留的规则

- 联系人资格、角色备注、头像、原始姓名与稳定身份分开。
- 群聊改名、加人、请人离开、解散与撤销，以及所有权限制继续有效。
- 群聊 `@全体成员`、点名回复策略、部分回信失败提示与重试继续有效。
- 回信逐条显现的现有节奏保留；失败不能清掉后续已到期的新消息调度。
- 主动来信仍只考虑已有联系人、好感度至少 100、全局每完成 15 个游戏回合最多一位，沿用游戏世界时间。
- 图鉴对玩家开放不等于 NPC 全知。手机模型只读取该角色有依据知道的内容，不把正文里的秘密或提示词标签灌进来信。

## 6. 朋友圈

### 6.1 参考邻舍的内容组织

采用「顶部操作 + 一条滚动动态流」：封面、轻量发布入口、筛选条、动态卡片一起滚动，避免把完整长发布表单固定在上方挤掉内容。

每张卡片分为作者与世界时刻、正文、配图、操作、评论。图片按数量排成清楚的网格；长评论可折叠。原图丢失显示原因，不渲染破图。地点与日期以游戏世界时刻为主；设备发布时间仅作为已有的辅助记录，不用于角色活动触发。

「全部 / 我的 / 有图 / 已点名」筛选只改变可见列表，不改变评论资格，不把其他角色的私聊显示为朋友圈。本轮仍是玩家发布、角色评论，不新增 NPC 自动发帖。

### 6.2 发布与编辑

点击发布入口后打开独立、可滚动的草稿弹窗：正文、点名、配图与说明在中间滚动，取消/发布在底部始终可达。编辑使用同样布局与明确的原动态版本校验。

保留正文 500 字、最多 9 张配图和纯图片动态。程序插入 `@` 也必须遵守 500 字限制；超过限制显示提示并保留草稿。发布/编辑失败不得清空文字和配图。

点名选择同时记录角色稳定身份。同名角色必须明确区分，不能取数组第一位；备注不改角色身份。被点名者回应及普通评论门槛遵守既有规则；联系人被移除或失效后，即使走本地失败补答也重新核验资格。

上传、相册选择、生成配图只加入当前草稿，确认发布才创建动态。编辑后是否重建评论沿用现有版本机制，不另加一套自动评论流水线。

### 6.3 朋友圈设置

设置也使用可滚动内容与始终可达的底部按钮。借鉴邻舍的分组形式，本轮只新增显示偏好：舒适/紧凑卡片、显示地点与世界时刻、默认展开评论。若隐藏世界时刻，仅隐藏显示，不删除保存记录。

显示偏好保存到本地设置的独立字段，由设置保存入口负责写入；回合收尾不得重写捕获的旧设置。普通好友评论门槛、点名必回应、确认生成才调用 API 等既定规则只作说明，不借布局改动开放另一套规则。

不接入邻舍话题库、NPC 自动发帖、现实时间定时生成或默认自动配图。这些属于新增玩法和潜在模型费用，超出本轮布局迁移。

## 7. 聊天照片与生图

手机照片维持「一次聊天回复完成后统一入口」，不是每条角色消息各有一个生成按钮。群聊选人、提示词库、英文外貌资料和玩家要求继续可用。

照片预览独立于聊天滚动层，中间能滚动，底部确认始终可见。选择词组或打开预览不调用 API；确认生成才调用已配置的接口。任务状态、失败原因和最终实际提示词的精简说明必须可见。

手机和相册预览绑定创建草稿时的人物资料版本；资料改变时要求刷新自动角色块或重新确认，不把旧发色和新发色拼在同一个提示词中。手工输入的玩家要求不能被无提示覆盖。

Latent 与 NovelAI 的最终请求都必须保护明确记录的人名/性别/外貌事实。若接口限制内无法容纳必要事实，则在调用前说明无法生成；不能静默丢掉资料后付费生成。手机/朋友圈仍只使用当前任务允许的公开外貌资料，不把关系七维、角色记忆或私密事件作为图片提示词。

## 8. 22 项复审问题的处理范围

详细复现与证据保留在原审查报告，不把其「待修」标记改成「已修」。建议实施顺序按风险分批；每个缺陷先增加反例测试，再修复对应正式路径。

| 批次 | 问题 | 必须守住的结果 |
|---|---|---|
| 1 保存与异步基础 | A01、A02、A03、A06、B03、B13 | 迟到图片/初始化不跨档，不回退新设置，代理可取消，流式结束不误超时，并发失败记录不丢 |
| 2 手机人物与投递 | A04、A05、A08、B04、B05、B06、B07、B08、B12 | 不泄漏秘密，不让退群角色迟到写入，解散可撤销，身份/资格/所有权在提交时仍成立 |
| 3 页面迁移与浏览 | A09、B09、B10、B11，以及本文件页面调整 | 小屏确认可达，图鉴关联跳转有效，字数及异常时间不会让界面崩溃 |
| 4 生图资料一致性 | A07、B01、B02 | 外貌版本一致，最终请求保留必要事实，裁剪和失败可见 |

分批不能把未完成的依赖伪装成已验收。例如 UI 可先演示，但真实群聊迟到回复的修复必须经过结算路径测试，不能只测新按钮。

## 9. 验收方式

### 9.1 自动检查

- 对 22 个缺陷逐项覆盖原报告反例，包括延迟结果、切档、同档并发编辑、取消、重复名字、失败补答及异常导入值。
- 页面测试核验菜单身份、左侧入口移除、未读徽标、快捷入口、同伴页保留、天赋操作和元素限制。
- 手机/朋友圈组件测试覆盖草稿隔离、发送快捷键、部分失败、编辑版本、图片选择/生成、字数保护与设置保存。
- 每批执行相关单测，最终执行类型检查、全量单测、回归、构建与已有体积检查。测试数量以当次实跑为准，不复用上轮数字作为完成证据。

### 9.2 实际浏览器检查

至少检查 1280×720、390×600、390×844 的布局，另检查浏览器缩放和中文输入法。发布、照片、设置、联系人/群管理的长内容均能滚动；确认按钮不被裁掉；弹窗焦点、Esc、关闭后焦点返回可用。

在正式游戏页面用隔离测试数据检查一轮私聊、群聊、点名、动态发布/编辑/删除、照片与元素天赋导航；真实玩家存档不作为可随意修改的测试夹具。使用假供应商完成可控失败测试；真实接口端到端调用与人物回复质量需单独说明是否实际测试，不能由假网络测试代替。

### 9.3 当前已经有与尚未有的证据

- 已有：本地交互原型；用户明确选择「手账融合」；原型 390×600 下设置与照片弹窗底部按钮可见且命中测试通过。
- 尚未有：正式页面迁移、22 项修复、正式浏览器验收、真实供应商端到端验证。原型结果不替代这些证据。
