# 手机照片与人物视觉资料

用户已确认：手机内预览确认 → 生图 → 聊天显示并收入相册。

## 人物资料

相册和手机共享人物姓名、性别、概括外貌、已记录外貌细项与常用穿着。发色、瞳色、身高、体重及已有且允许展示的三围读取现有档案，不生成缺失数值。沿用角色锚点启用及场景注入开关；锚点中的稳定特征优先，补充无冲突的结构化资料。词组转化器接收这些资料，模型改写后及本地精简均保留姓名、性别和辨识特征，继续遵守 1800 字符草稿和供应商最终上限。不新增角色档案补全功能。

## 手机操作

有对应 NPC 档案的角色消息提供“生成照片”按钮。玩家请求角色拍照并收到回复后，可在该角色回复下点击；群聊只选当前消息发言者，不把其他群成员自动加入画面。弹出独立照片编辑面板，显示人物身份和档案来源，可改拍照内容、正面/负面提示词并确认调用。仅选中的当前会话、选中消息之前的有限相关聊天用于提示词，不召回其他私聊，不自动付费生成。普通照片沿用普通生图接口与参考图设置，不提供 NSFW 入口或读取私密档案。

照片挂到选中的消息上（保留消息原文），同时保存为相册图片条目。手机只存相册 entryId/assetId 和 NPC ID 引用，不复制图片 payload，不改头像或好感度。生成失败显示错误，可重新确认重试；同一消息已有照片不重复生成，避免误扣费。

## 生命周期

沿用全局生图队列和通用供应商接口（包括 Latent）；任务在相册中有状态记录。点击取消或关闭照片编辑中止任务，关闭手机中止尚未完成的任务。切换存档/会话、删除消息/联系人后，迟到结果不得写入新档或别的消息。生成操作开始前和结果提交前分别核验会话、消息、NPC 和 session；提交时采用函数式合并保留期间新增消息和图片。

## 验收

1. 本地/模型精简后的头像与场景资料仍包含姓名、性别和已记录外貌细项，缺失信息不凭空出现。
2. 打开照片预览不发网络请求；确认才调用配置接口；关闭/重复点击不重复提交。
3. 成功后手机和相册都可见，同一条消息和相册引用在保存/加载后仍能解析。
4. 失败、取消、切档、会话删除和并发消息更新不会串档、丢消息、改头像或改角色数值。
5. 执行单测、TypeScript、构建、包体积门禁和完整回归；不调用真实付费 API。
