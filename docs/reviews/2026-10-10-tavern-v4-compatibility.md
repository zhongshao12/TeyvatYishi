# 糖糖 V4.0 与旧版正则包兼容记录

日期：2026-10-10。本轮仅修改预设导入、投递、纯文本正则和对应界面；不修改年龄、亲密事件或角色档案结算规则，也不提交、合并或推送 Git。

## 使用方法

1. 刷新应用，在设置的酒馆预设页重新导入 `【糖糖公司】V4.0.json`，选中并启用它。之前导入时已经丢失的扩展正则不能凭空还原，需重新导入原文件。
2. 该文件已带有 23 条正则。若仍需导入 `糖糖正则(老版本酒馆使用).json`，点击当前预设的「导入正则包」；它只修改当前预设草稿。
3. 点击「保存修改」。两个文件中的相同规则按内容和作用域去重，即使 ID 或作用域数组顺序不同，也不会重复执行或重新启用玩家已经关闭的规则。
4. 可使用本地审查、干跑预览和上下文投递报告检查启用项、宏展开及跳过原因。

## 实现边界

- 导入并持久化 `extensions.regex_scripts`；单独正则包支持数组、单条规则和 `regex_scripts` 容器。不会保留或执行 Tavern Helper 程序。
- 支持提示词的 in-chat 位置、深度和排序；保留项目输出合同和结算约束。
- 纯文本正则按来源（玩家、AI、世界书）、发送/显示范围、禁用状态及深度处理副本。捕获到的聊天文本不作为宏程序执行。
- 结构化历史可以投影为正文、摘要、悬念和选项的临时标签外壳，供旧包的历史摘要过滤使用；不会改写聊天记录。
- 主剧情原始回复不执行导入正则。显示替换不改变正文编辑器中的原文或存档；相册头像传递保持正常。
- 文风、篇幅和段落/状态信息要求进入请求；载体仍为游戏的 NarrativeTurn JSON，不切换到酒馆 HTML 页面。篇幅上限不会误变成下限或触发“字数不足”重试。
- HTML/CSS/脚本美化、自动发送和工具副作用不执行。此实现不是完整 SillyTavern 宿主，也不保证所有第三方扩展等价运行。
- 复杂重复模式、过长模式及过长处理文本会被保守跳过并说明原因；这是防卡顿措施，不是完整正则沙箱，也不是模型发送前上下文硬上限。
