## 1. 用户目标与范围

将变量、记忆和数据库作为同一项架构重构：1,000 回合完成正常长期运行验收，5,000 回合完成压力及故障测试，使世界状态、角色认知、历史经历和存档保持一致。目标是三个系统全面达到成熟可用，关键召回、分支隔离和恢复能力达到长期游戏级。

用户明确不要求保留现有存档的升级兼容，因此 2.0 从新档开始，不实现 1.6.0 到 2.0 的存档迁移。这个决定不授权删除现有数据库、存档文件或备份；新数据使用独立命名空间，旧档不能被新装载器误读。2.0 之后自身的数据格式升级仍须具备备份、校验与回退。

重构保留 React、手账融合视觉、现有内容资源、API 供应商适配及已经确认的业务规则。四层记忆与世界树继续作为玩家操作概念，但旧字符串数组与并行来源映射不再成为新核心的正式存储。

## 3. 核心原则与方案取舍

采用“当前状态 + 只追加的经核对事件 + 有界恢复快照”。当前状态负责快速读取，事件解释变化，快照提供明确恢复位置。恢复时执行保存的确定性结果，不重新让模型决定历史。

相比只修召回，此方案同时处理错误结算、认知边界与保存一致性；相比纯事件重放或云服务重建，避免每次装载依赖全部历史、外部部署与重新生成结果。首版重建本地数据组织，不为更换数据库名称而新增依赖。

不可违反的规则：

1. 原文是证据，不是任意指令的执行授权；模型响应、预设数据和历史材料不得伪装为系统规则。
2. 当前变量只能由注册的游戏操作修改，不能由摘要反向修改。
3. 世界事实与角色信念分开，公开可获取也不自动等于所有 NPC 已获知。
4. 已经可靠提交的事件不因摘要失败而消失。
5. 读取范围、提示词预算、历史保存量是三件不同的事。
6. 核心状态只在主存储提交完成后成为“已保存”；缓存失败不另造主数据。
7. 身份、分支与来源校验必须在持久写入边界执行，不能只靠 UI 提示。
8. 承认不能验证的内容：找不到证据不补造，未测性能不宣称收益，未知写入结果先查询再重试。

## 4. 数据职责与身份

### 4.1 核心集合

| 集合 | 内容与约束 |
|---|---|
| `journeys` | 独立开局 ID、玩家实例 ID、内容版本和格式版本；姓名不作主键 |
| `branches` | 分叉父分支、继承截止提交序号、当前核心提交序号及运行会话身份 |
| `sources` | 用户输入、有效正文、手机消息等不可变材料版本；原文与显示加工分开 |
| `factCandidates` | 候选类型、证据引用、参与者、提议值、核对状态和原因；不作世界真相 |
| `events` | 经核对事件、来源、参与者、实际变化、世界时刻及规则版本；不可原地改写历史 |
| `travelerState`、`npcState`、`worldState`、`inventoryState`、`questState`、`storyState` | 当前正式状态和必要版本；不内嵌全量对话或图片原文 |
| `operations` | 操作身份、冻结材料、执行结果、结算回执和已执行效果键 |
| `memories` | 摘要、层级、来源边、实际回合列表、时刻范围、可见范围、编辑与生成版本 |
| `npcKnowledge` | 角色获知事件的方式、告知者、证据、获知时刻及信念性质 |
| `commitments` | 参与者、成立证据、触发条件、履约状态和更新证据 |
| `jobs` | 后台任务身份、读入来源版本、步骤结果、取消状态、失败与重试进度 |
| `snapshots`、`saveNodes` | 不可变快照、核心提交位置、派生记录位置；可编辑存档槽只引用快照 |
| `assets` | 图片与二进制资源、校验值及引用；新资源先完整写入再发布引用 |
| `indexes` | 人物、地点、回合、世界时间、事件类型和关键词检索投影；可从来源重建 |

这些是逻辑集合，实施不得机械地为每个集合增加多层包装。经常同读同写的小状态可合并存储；持续增长的正文、事件、记忆及资源保持独立。

### 4.2 公共身份约定

- `journeyId`：每次新开局由宿主创建，不随玩家姓名变化。
- `branchId`：每条时间线独立；跨分支只能显式读取祖先截止位置之前的数据。
- `entityId`：本旅程的角色、物品、任务实例身份；原著目录 ID 与本旅程实例区分。
- `operationId`：一次主回合、手机互动或玩家操作的稳定身份；网络重试沿用。
- `sourceId` 与 `sourceVersion`：一份不可变材料版本；重骰与编辑产生新版本，不原地替换旧证据。
- `eventId`：宿主分配并随审核结果保存；不能仅靠姓名、数组下标或模型返回 ID 决定身份。
- `effectKey`：宿主根据已经审核的事件与注册规则生成，同一操作下同一效果只能落地一次。

文本指纹只用于变动检测，不是权限证明或事件身份。相似文字可能是不同时间发生的两件事；同一动作重复两次也必须有不同的可核对发生位置，不能靠相似度抹掉。

操作读集记录其读取的状态字段或记录版本。提交检查读集及写入目标；无关记忆整理不应使主回合天然过期，相关状态已变化时则重新验证或拒绝旧结果，不能盲目整体覆盖。

### 4.3 新档初始化

新开局通过注册的初始化操作创建旅程、首分支及基线状态。基线引用当次选择的玩家档案、开局配置、有效内容版本和原著资料，不继承上一旅程的手机、NPC 关系、物品、任务、记忆、世界时间或后台任务。设置与内容复用不等于旅程状态复用。

基线也需要可追查来源：用户建档选择标为玩家配置，原著资料标为内容资源，不伪装成已经发生的剧情经历。初始化完整写入后才发布可玩旅程，失败则保留可重试配置，不出现半个新档。尚未相遇的角色资料可用于图鉴或作者参考，但不能仅因资源存在就建立私聊联系人或授予共同经历。

## 5. 事件与证据契约

### 5.1 最小事件记录

`GameEvent` 包含 `eventId`、`journeyId`、`branchId`、`operationId`、`commitSeq`、`turn`、`type`、`actorIds`、`targetIds`、`evidenceRefs`、`occurredMoment` 或 `momentRange`、`ruleVersion`、`committedChanges`、`visibility`、`recordedAt`。`committedChanges` 记录实际提交前后值，不复制模型提议当作结果。

证据引用包含来源 ID、版本、叙事块身份及可精确复查的摘句或位置。用户输入中的意图、模型思考、输出协议、系统提示和显示正则替换文案不能冒充已发生的正文事件。采纳的正文块一经冻结不受后续显示正则修改影响。

系统固定奖励的依据采用宿主验证的规则引用，例如同行状态、日期跨度及规则版本；不能让模型自行填写“系统结算”获得白名单。手动编辑以玩家操作来源记录，不能伪造为历史正文。

### 5.2 核对、执行与整理状态分开

| 对象 | 状态 | 含义 |
|---|---|---|
| 候选事实 | `proposed / verified / pending / disputed / rejected` | 描述是否有足够依据，未提交前不等于世界事实 |
| 操作 | `draft / prepared / committed / failed / cancelled` | 描述执行阶段；回执丢失时先核查存储，不猜测失败 |
| 派生记忆 | `pending / active / failed / superseded` | 描述整理结果；失败摘要不得当有效生成结果召回 |

角色推测可以形成“该角色产生这一判断”的事件，但被推测的内容不能因此成为已确认世界事实。传闻保留说话者与可信程度，与真实状态独立。

### 5.3 历史更正

已提交事件不可原地改写。校正创建引用原事件的更正操作，按当前状态重新验证并记录结果；需要改变整段历史时创建分支。玩家编辑记忆改变表述或重要性，不隐式改变变量、约定状态或其他 NPC 的知识。

## 6. 变量协议、规则与提交

### 6.1 模型职责

沿用当前可配置的变量模型请求入口，输出候选事实，不输出任意数据库字段路径。候选必须包含类型、主体、对象、提议值和来源引用。身份消歧失败、证据不足或格式错误要可见，不自动创建伪 NPC、伪联系人或猜测数量。

本地叙事识别器与模型提议都进入同一候选核对入口，不能另设隐蔽写入旁路。不新部署小模型；模型未配置或提取失败时保留待结算材料，不用本地猜测冒充模型成功。

### 6.2 注册游戏操作

操作采用有明确含义和参数类型的注册入口：物品获得/消耗/交付/转移，角色加入/离队，世界时间/地点/天气变化，任务建立/推进/完成/失败，关系与档案更新，约定建立/取消/履行。自定义属性须登记类型、范围与权限。

复用既有数量、危险路径、稳定 ID、好感范围、任务门禁及年龄/私密字段保护。好感规则与同行每日奖励不因重构重新定值；正常角色互动的模型数值提议也必须经过现有规则和来源检查，不能只因笑容、台词或模型置信度就升级关系。

### 6.3 核对与依赖组

核对事实是否已发生，是否包含否定、计划、条件、转述或回忆；检查动作主体、接收者、物品归属、数量、任务前置与现状冲突。逐字命中只是必要来源检查，不能证明语义正确；无法由可靠证据与规则确定的高影响变化暂缓。

候选先按事件及依赖关系分组：交付物品、扣库存、任务进度与相关经历是一组。无依赖的明确组可以提交，待确认组不产状态命令；一个组内的必要效果不得静默丢掉一部分。所有选中的可提交组在同一核心事务中写入，状态变化及回执保持一致。

因含糊事实暂缓而缺失的后续条件不得假装已满足。玩家以后确认候选时，系统重新检查当前库存、任务与关系，将确认作为新的审核操作处理，不直接把旧快照写回。

### 6.4 一次结算的主路径

1. 创建稳定操作身份，保存玩家输入与基线读集；生成的正文先标记待结算。
2. 冻结有效正文与来源版本，提取并审核候选事实。
3. 构造可提交依赖组，确定注册规则与实际状态变化。
4. 在主存储提交边界检查分支、取消状态、读集、重复操作及效果键。
5. 同时保存已选事件、当前状态、基础知情与约定、核心回执及后台任务。
6. 持久提交完成后才发布已保存界面状态；进度和世界时刻从同一结果读取。
7. 唤醒派生任务；摘要失败不回滚第 5 步。

下一主回合不得以未结算正文当作已成立事实。提取或保存失败时保留输入和正文、显示明确恢复入口；含糊组不妨碍已经可靠提交的无依赖组继续游戏。

### 6.5 并发与幂等

主存储在同一提交边界执行重复身份与版本检查。多标签页、多实例或重试同时提交同一操作，只能一份结果获准生效；其他调用返回已经提交的回执或明确冲突。

幂等记录保存于本旅程长期账本，不受“变量窗口只显示最近若干条”影响。外部 API 可能重复收到生成请求，本地效果仍只提交一次；请求尝试和账本操作分别记录，不承诺供应商只计费一次。

取消在提交前有效；已经提交后取消只影响未完成后台任务，不回滚已发生事件。若发生“提交后、回执返回前”中断，恢复首先查询同一操作结果，不能再次扣物品或领奖励。

## 7. 单一世界时刻与剧情进度

当前世界时间只有 `worldState` 一个权威。事件持有不可变历史时刻：世界名、日期、时钟、天气、地点、旅行天数、回合和操作身份。后台重试继承该时刻，不读取完成时的现在补写。

主回合内明确先后事件可保存子事件顺序和有证据的时间范围；不因为缺少精确分钟而臆造中途天气或地点。同一回合跨越多地/多日的摘要必须标为区间，不统一伪装成终点现场。

沿用跨午夜、多日跨度和否定时间回退规则。历史回忆不推进当前时钟；手机等独立互动只读取当前游戏时刻，确需推进时间的动作必须走注册入口。后台完成、现实等待和重新开页不推进游戏时间。

主剧情回合计数与分支核心提交序号分开：手机、手动编辑等操作可以有独立序号，不伪造主剧情回合。当前篇章由已经提交的剧情节点派生，与变量、存档和显示一致，不能从摘要或篇章名称提及直接跳转。

## 8. 四层记忆、压缩与重建

### 8.1 一种记录，多种层级

`MemoryRecord` 同时持有正文、层级、来源事件/消息/记忆版本引用、实际回合列表、世界时刻区间、关联角色/地点、可见范围、重要性、固定保留状态、生成版本和编辑版本。

- 即时：最近动作与连续剧情，包含可追查事件及必要原文窗口。
- 短期：每个完整主回合的独立摘要。
- 中期：阶段事件链、任务或旅程摘要。
- 长期：稳定经历、重要关系和长期影响的整理视图。
- 世界树：这些记录的查看、维护与召回入口，不是另一份世界真相数据库。

底层统一来源图，不依靠数组下标和重复复制正文连接。正式变量、履约状态和角色知情直接读结构化状态，不以模型摘要是否提到它们为准。

### 8.2 逐回合与失败

每个已提交完整主回合创建独立摘要任务。按顺序处理，基础调用数至少与待总结完整回合数对应；分层整理及重试另计，UI 不声称固定价格。手机等来源按事件身份整理，不重复当成新主回合。

生成失败保留来源和错误，可从失败步骤恢复。成功摘要只在其来源版本、分支及取消校验通过后发布。模型启用时，本地降级文本不得冒充模型成功；显式关闭 API 的本地整理标记 `local` 来源。

### 8.3 同一压缩服务

自动整理、一键压缩和批量重建共用来源选择、独立阈值、生成、核验、版本提交与失败流程。逐回合短期摘要不再误用即时批次阈值当作中长期阈值；未达阈值的内容保留。

来源图记录实际并集，例如 `[3, 5]` 不宣称完整覆盖 3–5 回合。摘要可以替代读取视图中的低层条目，但不得删除唯一来源。重要结构化事实、约定与关系变化继续直接读取，不把全部语义正确性托付给摘要覆盖检测。

压缩不扩大知情范围。混合材料的摘要仅供所有来源都可见的接收者使用；权限不满足时读取可见叶子来源或安全子摘要，不将私密与公开事实混合后整体公开。

### 8.4 局部重建

开始时冻结旅程、分支、来源版本与选择范围；保存每个步骤的 staging 结果。选中范围全部完成并核验后发布新的有效记忆版本。范围外、跨范围、来源不明或玩家编辑的记忆不被整片覆盖。失败、取消或来源改变不发布半成品有效集合。

自动处理新来源可以继续；同一来源集的自动/手动压缩与重建须互斥。重试复用成功步骤，不重复请求；改范围或改来源创建新任务。同一来源的持续失败不得因每个新回合无限自动重试，进入待人工重试状态。

### 8.5 冷归档

冷归档指原文和旧记忆从热缓存转为数据库按需读取，不是删除。显示窗口、召回预算和来源保留分别配置。配额不足显示保存失败或备份/清理提示，不静默裁掉唯一历史；清理要核查分支、快照、记忆、未完约定与资源引用。

## 9. 角色认知与约定

### 9.1 基础知情记录

`NpcKnowledge` 引用角色实例、事件、获知方式、告知者或公开渠道、来源证据、获知时刻和性质。方式包括亲历、被告知、实际接触公开信息、传闻与推测。没有记录或可靠基础知识依据的私事按不知道处理。

参与角色列表不是所有旁观者名单；队伍成员身份不自动证明见证私密动作。成为手机联系人、收到消息、实际读到消息和得知公开报道都按对应业务证据处理，不能因相关人物姓名出现在原文就授予知识。

基本知情与约定骨架随事件提交，不依赖摘要任务。生成的人物印象是该角色视角资料，不自动成为全球人物性格或事实。原著图鉴允许玩家阅读，作者参考、角色常识和亲历知识分开标记，不赋予 NPC 对所有原著剧情和玩家私事的全知。

### 9.2 不同消费者

- 私聊：本人档案、本人可见事件与记忆、对应会话中可见消息。
- 群聊：对每位回答者构造可见资料；群内可见消息不等于该角色知道群外私事。
- 朋友圈：按发布可见范围和评论者知识选择来源，不传播未公开经历。
- 蒸汽鸟报：只读取已经确认公开的事件，禁止发送私聊或私密档案。
- 主剧情：作者参考与各角色知识分段标记，正文须守知情范围；真实模型仍需单独验证，不以提示词存在代替质量证据。
- 生图：消费外貌与用户要求等已有合法字段，不把关系账本、技术标记或私有记忆灌入画面提示词。

### 9.3 约定对象

约定包含 ID、参与者、内容、成立事件、类型化日期/地点/事件触发条件、是否明确循环、履约事件、状态及状态变化历史。状态为待履行、到期、已履行、已取消、已违约；到期不等于违约或完成。

世界时间推进只负责检查触发条件。共同旅行、交付或取消的可靠事件才更新履约状态。普通邀约不能自动成为指定日期的强制任务；默认一次性，未明确每年重复的生日约定不生成无穷循环。

主动联系继续遵守已有联系人、好感度至少 100、每完成十五个主回合全局最多一位、仅游戏内推进触发的规则。触发任务身份与全局冷却随相关核心状态保存，后台重试不再占一次新名额。

## 10. 统一召回与上下文

### 10.1 查询输入与步骤

输入包括旅程、分支截止位置、当前游戏时刻、相关角色、地点、玩家当前问题和调用目标。不是每次将全部历史或整个 NPC 库拼成检索字符串。

1. 过滤旅程、可达祖先范围、有效版本及来源状态。
2. 按接收者知识及消费者权限过滤；未知私密权限默认拒绝。
3. 查询人物、地点、事件类型、回合、世界时间与关键词索引。
4. 合并到期约定、未完任务、未解决冲突和固定的重要记忆。
5. 按关联、重要性、近期性与条件触发排序，并依据来源去重。
6. 组装必要事实、摘要与少量原文；保存选择与排除原因。

首版采用本地结构化及关键词检索，不固定未经测量的评分公式。语义检索只在标注测试证明词面检索存在重要漏召回后提出独立变更，不自动安装依赖。

### 10.2 上下文预算

预算只决定可选记忆的选取与表达，不是整请求硬上限。近期连续剧情、重要固定事实与确已触发的约定优先，低关联历史可以不选。关键内容超过目标预算时报告原因，不静默删除，也不修改数据库原文。

玩家输入、系统规则、酒馆预设、世界书和其他已有主请求投递规则不因本次记忆预算被擅自裁剪。估算 tokens 与实际 API usage 分开；未知窗口不猜测为 32K 或 1M。具体检索 K、召回预算和评分参数由实施计划依测试集冻结，不在设计阶段宣称最优数值。

世界树命中不关闭其他层。相同事件的多个摘要可以选择较合适表示，但不通过文字相似度删除不同事件。待确认候选仅在诊断/询问所需的标记区展示，不能混入“已发生历史”。

## 11. 存储、事务与恢复

### 11.1 统一接口与格式隔离

访问层暴露本领域查询、核心提交、派生版本提交、快照、导出/导入与完整性检查。React 与模型客户端不得直接访问 IndexedDB 对象存储或 Tauri 文件路径。两种后端接受同一套行为契约，不各自实现好感、时间或召回规则。

新 Web 数据使用独立数据库命名空间，桌面使用独立核心数据目录；不修改原数据库版本以偷偷升级旧档。新导出清单拥有独立格式标记、版本与内容校验，不复用旧字段使 v1.6 装载器误读。具体对象存储名称和版本常量在共同契约实施计划冻结，不据此更改当前应用发布版本。

设置、导入预设、世界书及玩家内容编辑不是被放弃的旧档。优先复用独立设置服务和现有内容更新规则；若设置键确需转换，单独列明映射与保护，不自动清空密钥或用户资料。

### 11.2 IndexedDB 主存储

模型请求及耗时计算在事务之外，事务内仅核查版本、重复身份并写入核心状态、事件、回执与后台任务。以事务完成事件为保存成功依据，单个请求成功不等于整批已提交。

索引建立旅程/分支/核心序号、角色、地点、事件类型、游戏时间、约定状态与关键词查询入口。索引与实体有明确版本；派生索引滞后时可以回退有限范围的已提交事实查询并显示整理状态，不退回全库热加载。

### 11.3 Tauri 文件主存储

新文件后端用不可变数据块、提交清单和当前有效版本指针表达一次逻辑提交：

1. 获取跨实例的相应写入锁，核对前一版本和操作结果。
2. 写入所需新状态块、事件块、回执与任务，同步必要文件并校验引用。
3. 写入包含预期序号、引用和校验值的完整提交清单。
4. 使用同路径/同文件系统的安全替换发布当前有效指针，作为逻辑提交点。
5. 完成回执；派生索引可从有效清单重建。

发布前中断留下不可见 staging，恢复仍读上一完整提交；发布后回执中断按操作身份读回结果，不再次执行效果。恢复检查必要引用与校验，当前提交损坏时报告并使用可验证的上一完整提交，不能静默拼接不同提交版本。

IndexedDB 缓存不是第二个主存储，缓存失败不得把另一份数据冒充最新。单文件原子替换不等于多文件事务，也不等于所有硬件断电零损失；同步、指针替换、多进程和重启故障须单独实测。文件方案不能通过门禁时，提交桌面后端 SQLite 变更提案，不悄悄改引擎或降低门禁。

### 11.4 故障结果

| 发生位置 | 正确结果 |
|---|---|
| 输入保存或模型请求前失败 | 玩家输入保留；没有核心状态效果 |
| 正文完成，提取/审核失败 | 正文待结算；可恢复，不能继续引用为已成立事实 |
| 核心事务提交前中断 | 上一完整状态仍有效；记录可恢复材料 |
| 核心提交后回执丢失 | 查询原操作回执，不能再次执行 |
| 摘要、压缩或索引失败 | 已提交事件仍有效，派生任务可独立重试 |
| 切档、取消或相关来源变动 | 迟到结果拒绝写入；不能复活被取消任务 |
| 图片写入中断 | 不发布破损资源引用；已有效图片不被回滚 |
| 配额不足或文件占用 | 显示保存失败及恢复选择，不显示已保存 |

恢复服务处理运行中断；执行器负责确定性效果；索引可重建，原文和已提交事件不可凭空重建。外部备份仍是设备/浏览器资料丢失的保护，不宣称本地数据库能恢复已经被清除且无备份的数据。

## 12. 快照、分支、导出与版本升级

当前状态按需读取，快照引用明确核心提交位置及派生记录版本。恢复只应用快照之后有界范围内的已提交确定性效果，不重新生成正文或从第一回合重放。快照生成范围与恢复跨度上界在实施计划设定并通过 5,000 回合测试，不能无限延长恢复链。

手动存档槽更新引用一个新的不可变快照，不覆盖后代依赖的旧快照文件。保存更新当前槽；另存为新增节点。自动节点保留最近十回合的可见恢复入口，来源和幂等记录不随窗口一起截掉。

从旧恢复点继续游戏、重骰或改变既有正文时建立明确分支。祖先事件可共享但受分叉截止序号限制；未来事件、未来生成的带新事实摘要、父分支后来的人工编辑及后台结果不能进入子分支。纯派生资料只有全部引用来源可达、版本一致且可见性通过时才能复用。

清理先计算所有分支、快照、来源、约定、记忆及资源引用，避免删掉仍被引用的基线。孤立 staging 和无引用缓存是可清理候选，不授权自动删除玩家历史。

导出包包含清单、核心状态、恢复位置、可达事件/来源、记忆版本、必要资源和完整性校验。系统 API 密钥不进入导出，私密聊天和档案属于玩家数据，导出时要提示其包含范围。索引可以重建，不要求携带所有运行缓存。导入在隔离 staging 中校验格式、引用、容量及重复身份，完整通过后才发布新旅程。

不提供 1.6.0 迁移，但 2.0 后续升级仍采用版本化转换、升级前备份和失败回退；未知未来版本拒绝装载，不试图按旧字段猜测。格式升级不能在启动时偷偷删除唯一源数据。

## 13. 后台任务与界面

后台任务有独立控制器和持久状态，保存来源版本、原旅程/分支、步骤材料与生成配置指纹。成功步骤复用，失败步骤重试；有限自动重试用现有配置，耗尽后转人工处理，不因新回合无限重试。

后台提交只写其拥有的派生字段或安全版本补丁，不替换整个核心状态。切档、卸载、重开和取消需要失效运行任务；刷新后先显示原任务状态及恢复入口，不未经授权自动重发可能计费的请求。批量处理先显示预计基础调用数与范围。

UI 沿用既有手账页面，增加或整合：

- 结算回执：已保存的具体变化、来源、待确认项与冲突理由。
- 世界树：按回合/人物/地点查找，查看原文、固定条目、一键压缩与局部重建。
- 同伴：共同经历、知情方式和未完约定；摘要不冒充正式关系数值。
- 失败中心：区别主请求失败、待结算、保存失败、后台整理失败。
- 召回诊断：实际选中内容、来源、权限和排除原因，区分预览与真实请求。
- 存档：格式与恢复位置明确，旧格式不混进可继续的 2.0 列表。

大列表分页或按需加载，消息滚动及弹窗焦点保持既有行为。不能为实时进度每次重读数据库全量内容；界面依赖本页所需查询和订阅，退出页面及时取消读取与释放资源。

## 14. 可维护的模块边界

建议以少量职责模块组织，不预建每表一套抽象层：

```text
core/
  contracts/       共同数据与版本
  sources/         原文、身份和证据
  settlement/      审核、规则、依赖组和核心提交
  memory/          摘要、压缩和重建
  knowledge/       角色认知与约定
  retrieval/       查询、排序和上下文
  persistence/     后端、快照、完整性与格式升级
  jobs/            派生任务及恢复
```

公共内部数据只有一份正式定义，中文 UI 标签不产生第二套状态模型。旧中文模型/Legacy 转换在新核心接入完毕后退出正式路径；过渡适配只在单边界转换，不长期保持互相写回。

模型客户端负责请求，不读写数据库；规则函数可在没有 React 和真实数据库时测试；存储后端不了解好感和故事规则；组件通过应用操作与查询访问数据。避免新“大总管”把所有领域逻辑收回一处；协调层只安排顺序、身份与事务。

## 15. 交付阶段与第一份可试用成果

采用 `blueprint-set` 组织：本文件为总设计，实施计划由一个共同阶段索引及存储/恢复、变量/事件、记忆/认知三个领域文件组成，不预建源码空壳。2026-10-14 已建立总索引 `docs/superpowers/plans/2026-10-14-unified-core-2-plan.md` 与根目录 `NEXT.md` 唯一续接指针，没有另设并行进度账本。

| 阶段 | 输入与交付 | 退出条件 |
|---|---|---|
| 1 共同契约 | 本设计、旧规则盘点；身份、版本、权限、事件和时间定义 | 无重复状态正典，规则与拒绝路径明确 |
| 2 可靠底座 | 新隔离存储、索引、核心提交、快照、分支和恢复 | 两端行为契约及提交中断测试通过 |
| 3 完整回合 | 原文→审核→规则→事件→保存→读档与可查回执 | 重试不重复生效，失败材料保留，关键变化可追溯 |
| 4 记忆与认知 | 逐回合任务、分层、压缩/重建、知情和约定 | 失败不丢事件，来源与权限保持完整 |
| 5 统一召回与消费者 | 主剧情、手机、新闻、任务、相册等受控查询 | 无旧核心写入旁路，私密资料不越权投递 |
| 6 长期验收 | 冷归档、性能、1,000/5,000 回合、运行恢复与 UI 检查 | 质量、性能、体积和真实宿主门禁达到冻结标准 |

第一份可试用成果不是空数据库页面：玩家新开局，得到/交付物品，与角色形成约定，看到真实状态与回执；刷新、重复结算仍一致；后续情境可以召回该约定和出处。至少演练一次保存或摘要失败并恢复。最后由玩家亲手试用并提出一次有目标的修改，再在授权下验证改动，不能用静态截图替代接受。

后续成长方向是经过漏召回证据支持的语义检索，以及实际后端门禁支持的引擎替换。分布式服务、自动云同步、旧档移植和无证据的功能扩张进入暂存，不计为首版完成项。

## 16. 验收目标、口径与未验证边界

全部指标为待实施验收目标，不用旧版测试数替代。

| 项目 | 门禁与测量口径 |
|---|---|
| 长期规模 | 1,000 回合正常模拟；5,000 回合压力、查询与恢复测试，覆盖实际增长的手机/事件/摘要负载 |
| 状态一致 | 已冻结测试集中无重复奖励、负库存、未授权写入、事件/状态/回执不一致 |
| 幂等与并发 | 相同操作重复、同时、回执中断重放均只有一份效果；超过 UI 历史窗口仍有效 |
| 来源完整 | 所有重要事件和有效摘要来源可解析，真实回合缺口保留；不补造证据 |
| 明确约定 | 日期/地点/事件触发测试全部通过；提醒不算履约，已履行不重复触发 |
| 召回覆盖 | 人工标注的非空相关事件测试集 Recall@K 至少 90%；按事件身份计数，不用重复摘要刷命中 |
| 知情隔离 | 确定性权限测试无越权材料；主模型的自然语言知情表现另做人工检查 |
| 检索耗时 | 固定设备/浏览器/后端/数据集下，本地结构化候选检索 P95 目标不超过 200 ms；不含模型请求 |
| 保存与恢复 | 提交前/后、切档、取消、刷新、多实例、占用、配额和格式升级注入失败均保持可解释状态 |
| 导出与导入 | 引用完整、校验可验证、未知格式拒绝、系统密钥不进入事件或导出 |
| UI 与工程 | 有关联断言的自动化、类型、Lint、全量单测、回归、构建、资源及体积门禁；小屏与真实宿主另验 |

实施计划在改产品代码之前冻结召回 K、评测集及留出集、设备信息、正文长度分布、NPC/手机负载、资源体积、查询次数与快照恢复跨度。P95 的计时区间包括必要本地读入与结构化过滤，冷启动、热缓存以及整体召回耗时分别报告，不混入模型等待时间。未冻结这些条件前不报告达标。

至少覆盖下列场景：

1. 同名玩家两次开局、改名、手机备注与别称均不串身份。
2. 明确获得/交付与计划/否定/回忆对照；同操作十次重放及同时提交。
3. 组内扣物品成功但任务故障的注入不能产生半组结果。
4. 次日、多日、午夜及同日回退；主剧情、手机、新闻、NPC 与存档一致。
5. 第 80 回合生日约定到第 650 回合触发，已履约、取消和未到期版本作负例。
6. 私聊、旁观者、公开报道、传闻、作者参考、混合权限摘要以及多角色群聊。
7. 15 个完整回合有 15 个来源摘要；第 8 个失败重试不重调 1–7；不同层阈值正确。
8. 局部重建、人工编辑、删除来源、切档、重骰与迟到完成均不覆盖无关有效资料。
9. 分支截止、旧恢复点继续、父分支未来内容与未来人工修改不进入子分支。
10. 摘要失败仍能继续已有可靠状态，索引损坏可修，原文丢失则明确缺失。
11. 自动节点最近十回合轮换但旧重要经历和长期幂等记录仍可查。
12. 5,000 回合开启页面不把全部正文/图片加载到顶层；记录加载、保存、内存及主线程长任务。

长回合自动化使用可重复的本地材料及模拟 API，不能冒充数千次真实供应商调用。真实模型事实提取、召回后自然表达、取消耗时、Windows 桌面重启/断电和移动端键盘须分别取证；没有实际观察就标未验证。不能声称对全部设备、浏览器资料被清空或硬件损坏具备绝对恢复保证。
