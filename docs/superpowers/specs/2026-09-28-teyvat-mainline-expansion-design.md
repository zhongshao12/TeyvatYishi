# 蒙德至纳塔主线细化设计

日期：2026-09-28

## 意图与边界

这是已确认四批改造中的第三批。把蒙德、璃月、稻妻、须弥、枫丹、纳塔的内置主线从章节概要扩展成可游玩的连续场景，同时保持“自定义旅行者与空／荧并存、可偏离原著轨道”的项目设定。原著事实是叙事参照，不是要求玩家无论如何都重演原著的强制脚本。

保留现有系列 ID、分段 ID、分段组号和存档中的已完成／跳过／偏离状态。已完成的旧存档不因内容更新而重开章节；仍在进行中的旧存档可从当前分段内安全进入新场景。诺德卡莱、支线活动、斗地主和图鉴改造不属于本批。游戏时钟、NPC 认知边界、队伍和背包继续由现有独立系统结算，不由剧情资料直接改写。

## 当前代码与资源的事实

- 运行时从 `public/data/story-weaving-canon/<系列ID>.json` 加载内置系列；`data/storyWeavingPreset.ts` 按分段 ID 合并存档进度。`data/storyWeavingCanonDecomposed.json` 不在这条运行时加载路径上，不应被当作第二份可编辑真源。
- 蒙德三幕各有四个分段，但其他多数系列只有一个分段；枫丹和纳塔各有三个分段。大多数非蒙德段只有一句概括和一个笼统事件，缺少过渡、触发、人物所知与可偏离处理。
- 当前 JSON 中的事件大多使用 `事件`，角色推进使用 `角色`／`推进`，而 `models/storyWeaving.ts` 只接受 `事件名`／`事件说明` 与 `角色名`／`本段变化`。归一化时无名事件和无名角色推进会被过滤。这是内容实际未生效的阻断问题，必须先通过失败测试确认，再统一修正资源字段并加入资源校验。
- `services/storyWeaving.ts` 只把当前、相邻分段的有限条事件和事实投递给模型；`services/storyProgressService.ts` 用结束状态和正文证据判定分段推进。不能把整国扩写正文一股脑塞进每回合提示词，也不能仅凭提及事件名就宣布玩家亲历或完成。

## 方案比较与选择

1. **推荐：保留现有分段，新增轻量场景节点与场景游标。** 分段 ID 和旧进度完全稳定；每段可拆为若干场景，运行时只投递当前节点及下一节点短提示；节点提供事实锚点、入场门槛、完成证据和偏离建议。需要少量模型、归一化、存档与进度服务改造。
2. 把每个现有分段拆成多个新分段。可直接复用分段推进机制，但会改变分段组号、旧存档锚点和跨系列跳转；旧档最容易错位。
3. 只把现有 `原文内容` 和 `本段概括` 写长。数据改动少，但仍只有单一章节级推进，提示词容易膨胀，也无法区分当前场景和人物所知。

采用方案 1。结构化节点用于定向提示与检验；章节级完成仍以已有分段进度为最高优先级，场景节点不能独自跳过或复活分段。

## 数据契约与存档

在 `剧情编织分段` 上增加可选 `场景节点` 数组，节点字段限定为：稳定 `id`、标题、地点与参与角色、简短场景目标、进入条件、原著事实锚点、玩家可见信息、NPC 分别可知的信息、可偏离切口、完成证据、收束后果。事实锚点区分“开场时已经成立”与“只有场景完成后才成立”；未知事实不得提前写入角色台词。节点不复制长篇原著文本，不携带会直接执行的状态变更指令。

节点 ID 使用所属旧分段 ID 加稳定后缀，发布后不复用或重排含义。进度锚点可选保存 `当前场景ID` 与 `已完成场景ID`，只对当前分段有效。旧档没有这些字段时，以当前旧分段第一个未由明确历史证据覆盖的场景初始化；无法确认时停在首场景，而不是推断已经历。已完成、已跳过、已偏离的旧分段不重开。加载新内容时按稳定 ID 合并进度，内容以新内置资源为准，玩家运行状态与手动注入设置以存档为准；需要覆盖目前旧版持久化合并可能以旧文案遮住新版内容的行为，并用迁移测试证明不会丢进度。

先修正现有资源的事件、角色推进字段，再扩充；资源校验要求每个事件有非空 `事件名` 和清晰 `事件结果`，每个角色推进有非空 `角色名`，节点 ID 全局唯一，引用的分段存在。构建／测试时发现无效资源应失败，不再静默丢弃。可做兼容读取旧字段的短期迁移，但内置资源统一使用正式字段，不把兼容别名作为长期写入格式。

## 内容与叙事规则

六国主线按现有系列和分段顺序逐国补足“到达与动机 → 调查／结识 → 冲突升级 → 关键抉择 → 后果与下一地过渡”。每个旧分段通常拆成 2–5 个短场景；已有蒙德段可根据内容适当少于此数。每个场景写可执行的互动目标、至少一个明确的完成证据、涉及人物的认知边界，以及一条不篡改既有事实的偏离路径。避免为了凑数量重复同一对话、临时生成无关路人或把任意主角行动硬套成原著结局。

“原著事实锚点”只描述世界的默认情况与因果约束，并标明成立时机；若当前存档已经偏离，以玩家确实经历的历史、世界状态与人物可知信息优先。偏离时节点可以暂停、改写目标或被合理跳过，并记录原因；不能暗中将跳过记作亲历。原著角色的立场、称呼和私人信息不因共享章节数据而自动全知。自定义旅行者、空、荧的在场身份按开局档案和现有队伍状态决定，内容不得默认为三人同时随行。

内容写作以项目现有原著资源为底稿；涉及具体官方情节、人物关系与时间顺序时再核对可靠的原始资料，并在维护文档留下来源和必要的不确定性。若与项目已发生的 IF 剧情冲突，提供“默认原著／偏离后”两种提示，而不是覆盖存档事实。章节摘要面向模型保持短小；可读的详细文案保存在资源中，按需展示或局部注入。

## 投递、推进与失败处理

模型每回合至多收到当前场景的目标与必要事实、一个下一场景预热，以及当前分段的硬约束；历史场景只保留已确认结果的压缩摘要。`soft` 门禁只能提供氛围和防抢跑信息；`strong` 门禁才提供当前场景的具体互动目标。每类文本设定长度预算，不因六国内容扩写而线性增长。世界树与历史对话继续负责远期记忆，不在主线提示中重复长篇回放。

场景推进由玩家行动、已生成正文和明确的结算证据共同支持。提到地点、人物或事件标题只能成为弱证据；完成必须能对应节点的结果，且不能与否定／阻断语句冲突。证据不足保持当前场景；明确偏离则记录偏离原因并选择暂停、改路或跳过，而不是强制播原著过场。场景末尾与原有分段推进统一结算，防止一次回复连续跨越多幕或把下个国家提前标为已完成。资源加载失败时保持当前可用进度并给出可诊断错误，不退回一份内容更旧、字段不匹配的隐藏真源。

## 分批实施和验收

1. 先写失败测试复现内置 JSON 事件／角色推进被过滤、旧文案覆盖新资源和旧档锚点风险；修复资源字段、加载合并和资源校验。
2. 增加场景节点模型、归一化、存档游标与证据推进；测试旧档、新档、手动跳过、IF 偏离、角色知识边界及不能跨段抢跑。
3. 分国扩写蒙德、璃月、稻妻、须弥、枫丹、纳塔；每国做资源合法性、场景顺序、事实门槛、人物在场与老存档回归。保留旧系列／分段 ID。
4. 调整模型投递为当前场景窗口并测量提示词体积；模拟长会话、开局自定义旅行者与已偏离剧情。最后运行全量测试、类型检查、Lint 和生产构建。

验收时，六国均能在游戏中逐场景推进；故事不会只剩一句概要，也不会为追原著改写玩家已发生的事件。旧存档位置和已完成状态稳定；无名事件／角色推进在资源校验时被发现；长主线不会把六国全文同时送入模型。
